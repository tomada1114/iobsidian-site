整えてから変えるか、変えてから整えるか第1章 / 全7章

「動きを変える」と「形を整える」は、別の作業として扱います

コードへの変更には、プログラムの動きを変えるものと、動きを変えずに形だけを直すものがあります。この章では、二つを一つの変更に混ぜると何が起きるかを確かめ、手を動かす前に二つを仕分ける問いを練習します。

読了 約8分学習テキスト

この章で分かること

  • 動きの変更と形の変更を混ぜると、レビューで何が起きるのか
  • 二つの変更は、確かめ方と元への戻しやすさがどう違うのか
  • 手を動かす前に、どんな問いで二つを仕分ければよいのか
  • 練習問題：変更の一覧を仕分ける

01同じ変更を、二通りの出し方で比べます

入社2年目の佐藤さんは、社内の備品貸出システムを担当しています。ノートパソコンやプロジェクターを借りると、返す期限が自動で計算されます。今回の依頼は「貸出期限の計算から、土日に加えて祝日も除いてほしい」というものでした。期限を計算する関数は、次のように書かれていました。

def due_date(start, days):
    d = start
    n = 0
    while n < days:
        d = d + timedelta(days=1)
        if d.weekday() < 5:
            n += 1
    return d

佐藤さんは読み始めてすぐ、d と n が何を表すのかで手が止まりました。そこで佐藤さんは、祝日の条件を加えるついでに、変数の名前を day と counted に付け直しました。あわせて、その日が営業日かどうかを判定する部分を、別の関数 is_workday に切り出しました。ここから先は、同じ作業を二通りの出し方で比べます。

一つ目の出し方では、佐藤さんは名前の付け直しと関数の切り出しと祝日の条件を、一つのコミットにまとめてレビューに出しました。差分は20行ほどです。レビューを担当した先輩は、変わった行を1行ずつ見ながら、その行が動きを変えているのか、名前が変わっただけなのかを判断する必要がありました。先輩は「祝日の判定がどこに入ったのか、すぐには見つからない」とコメントを返しました。

この本では、プログラムの動きを変えずに、コードの形だけを小さく直すことを整える、その作業を整頓と呼びます。佐藤さんの作業のうち、名前の付け直しと関数の切り出しは整頓にあたります。

二つ目の出し方では、佐藤さんは同じ作業を二つのコミットに分けました。一つ目は名前の付け直しと関数の切り出しだけで、メッセージを「整頓: 期限計算の変数名を付け直し、営業日の判定を関数に切り出す」としました。二つ目は祝日の条件の追加だけで、変わったのは is_workday の中の1行です。二つ目のコミットまで終えた後の関数は、次のようになりました。

def is_workday(day):
    return (day.weekday() < 5
            and not is_holiday(day))

def due_date(start, days):
    day = start
    counted = 0
    while counted < days:
        day = day + timedelta(days=1)
        if is_workday(day):
            counted += 1
    return day

先輩は一つ目のコミットを「計算の結果は変わらないか」だけを確かめながら読み、二つ目のコミットを「祝日が正しく除かれるか」だけを確かめながら読みました。確認は10分ほどで終わりました。

02動きの変更と形の変更は、確かめ方が違います

ここで、二つの言葉を決めておきます。振る舞いは、利用者や他のプログラムから見えるプログラムの動きです。同じ入力を与えたときに返る結果や、画面に表示される内容が振る舞いにあたります。構造は、コードの内側の形です。変数の名前、関数の分け方、処理を書く順番が構造にあたります。この二つの言葉で言い直すと、整頓は、振る舞いを変えずに構造だけを小さく直す作業です。整頓は、リファクタリング（外から見える振る舞いを変えずに、内部の構造を理解しやすく変更しやすくする変更）のうち、特に小さなものを指します。

二つの変更では、レビュアーやテストが確かめることが反対になります。振る舞いの変更では「意図したとおりに結果が変わったか」を確かめます。祝日を含む期間を入力して、期限が1日後ろにずれることを見ます。整頓では「結果が何も変わっていないか」を確かめます。整頓の前と後で、同じ入力に同じ期限が返ることを見ます。

二つが一つのコミットに混ざっていると、レビュアーは変わった行ごとに、どちらの確かめ方を使うかを決めなければなりません。判断を一つでも誤ると、意図しない動きの変化を「名前が変わっただけ」と読み飛ばすことになります。差分が大きくなるほど、名前の変更だけの行が多くなり、動きを変える数行がその中に埋もれます。レビュアーが疲れてくる後半ほど、見落としが起きやすくなります。

書いた本人にとっても、混ぜた変更は扱いにくくなります。テストが失敗したとき、原因が祝日の条件にあるのか、名前の付け直しのどこかにあるのかを切り分ける必要があるからです。分けておけば、整頓のコミットの後でテストが通っていることを確かめた時点で、原因の候補は祝日の条件の1行に絞られます。

元に戻すときの手間も違います。整頓は、気に入らなければ名前を元に戻したり、切り出した関数を元の場所に書き戻したりすれば、前の状態に戻ります。利用者には何も届いていないので、戻しても誰も困りません。振る舞いの変更は、いったん本番に出て利用者が使い始めると、戻すのが難しくなります。祝日を除いた期限で備品を借りた人がいれば、計算を元に戻したときに、その人の期限をどう扱うかを決める必要があります。

03手を動かす前に、一つの問いで仕分けます

二つを分けて出すには、コードを書き始める前に、これからする作業を一つずつ書き出し、次の問いで仕分けます。

「この作業で、外から見える動きは変わるか」

変わらないと答えた作業は整頓のコミットに、変わると答えた作業は振る舞いの変更のコミットに入れます。コミットメッセージの先頭には「整頓:」か「変更:」を付けます。先頭の語を見るだけで、レビュアーはどちらの確かめ方で読めばよいかが分かります。

佐藤さんの作業を仕分けると、変数名の付け直しと営業日の判定の切り出しは「変わらない」、祝日の条件の追加は「変わる」になります。順番は、整頓を先にしました。名前が分かりやすくなった後のコードに祝日の条件を加えるほうが、どこに1行足せばよいかが見つけやすいからです。

この問いには一つ前提があります。整頓の後で「動きが変わっていない」ことを確かめる手段が必要です。期限の計算を自動で試すテストがあれば、整頓のたびに実行して同じ結果が返るかを見られます。テストがなければ、手で試す入力と期待する期限を三つほどメモしておき、整頓の前後で同じ結果になるかを確かめます。

つまずきやすいところ

確かめる手段がないまま大きく整えると、整頓のつもりで動きを変えてしまうことがあります。たとえば、< を <= に書き換えると、見た目はわずかな違いでも、期限が1日ずれます。確かめる手段が手作業しかないうちは、1回の整頓を名前1つ、関数1つの大きさにとどめます。

04練習問題

ある通販サイトの注文確認メールを送る処理に、次の作業をします。それぞれが振る舞いの変更か、構造の変更（整頓）かを答えてください。

  1. 関数の中で3回出てくる o という変数名を order に付け直す。
  2. メールの件名を「ご注文ありがとうございます」から「ご注文を受け付けました」に変える。
  3. どこからも呼ばれていない関数 old_format を削除する。
  4. 送料の計算で、合計金額が5,000円以上なら送料を0円にする条件を加える。
  5. 税込み金額を計算する式 price * 1.1 を、TAX_RATE = 1.1 という名前の定数を使う形に書き換える。

05解答と解説

  1. 整頓。名前が変わっても、メールの内容も送る相手も変わりません。
  2. 振る舞いの変更。件名は受け取る人に見えるので、外から見える動きが変わります。文字だけの変更でも、利用者に届く結果が変わるものは振る舞いの変更として扱います。
  3. 整頓。ただし条件付きです。本当にどこからも呼ばれていないことを、コード全体の検索で確かめてから消します。別のプログラムから名前で呼ばれていた場合は、消すと動きが変わります。
  4. 振る舞いの変更。同じ注文でも請求額が変わります。
  5. 整頓。計算の結果は同じです。定数の値を書き間違えると結果が変わるので、整頓の前後で同じ注文の税込み金額を比べて確かめます。

迷いやすいのは、件名のような文字だけの変更と、使われていないコードの削除です。判断の基準はどちらも同じで、利用者や他のプログラムから見える結果が変わるかどうかを問います。

3行まとめ

  1. 動きを変える変更と、動きを変えずに形を整える変更は、確かめることが反対なので、別のコミットに分けて出します。
  2. 形を整える変更は利用者に届かないのでたいてい簡単に元に戻せますが、動きの変更は利用者に届くと戻しにくくなります。
  3. 手を動かす前に「外から見える動きは変わるか」と問い、整頓の結果が変わっていないことを確かめる手段を用意します。
