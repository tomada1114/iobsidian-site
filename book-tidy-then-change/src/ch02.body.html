整えてから変えるか、変えてから整えるか第2章 / 全7章

読んでいて手が止まったところに、小さな整頓の型を当てます

コードを読んでいて手が止まる場所には、止まる理由があります。この章では、止まった理由ごとに当てる小さな整頓の型を、短いコードで一つずつ確かめます。どの型も数分で終わり、気に入らなければすぐ元に戻せる大きさです。

読了 約8分学習テキスト

この章で分かること

  • 読んでいて手が止まった場所を、なぜ整える価値があるのか
  • 止まった理由ごとに、どの整頓の型を当てればよいのか
  • 型を当てるとき、どこで慎重になればよいのか
  • 練習問題：短いコードに当てる型を選ぶ

01手が止まった場所は、次に読む人も止まる場所です

この本では、プログラムの動きを変えずに、コードの形だけを小さく直すことを整える、その作業を整頓と呼びます。

高橋さんは、会議室の予約サービスを作る会社に中途入社したエンジニアです。最初の仕事は、料金の計算に「学生は半額」という条件を加えることでした。料金を計算する関数を開くと、次のコードがありました。

def fee(room, hours, member, x):
    if member is not None:
        if hours > 0:
            base = room.price * hours
            if member.rank == "gold":
                return base * 0.8
            return base
    return 0

高橋さんは3か所で手が止まりました。if が3段に入れ子になっていて、どの条件で0円になるのかがすぐには読めません。0.8 が何の数字かが書かれていません。引数の x は、関数の中で一度も使われていません。ここから先は、同じ場面を二通りに書きます。

一つ目の高橋さんは、止まった理由を気にせず読み進めました。15分かけて入れ子の条件を頭の中でたどり、0.8 はゴールド会員の割引だろうと見当をつけ、学生の条件を3段目の入れ子の中に足しました。if は4段になりました。翌月、別の人が同じ関数に「平日の昼は1割引」を足そうとして、やはり15分かけて同じ入れ子をたどりました。

二つ目の高橋さんは、手が止まるたびに、止まった理由をメモに一言書きました。「入れ子が深い」「0.8 の意味が分からない」「x が使われていない」の三つです。学生の条件を足す前に、この三つにそれぞれ型を当てて、数分ずつ整えました。整えた後の関数は次のとおりです。

GOLD_DISCOUNT = 0.8

def fee(room, hours, member):
    if member is None:
        return 0
    if hours <= 0:
        return 0
    base = room.price * hours
    if member.rank == "gold":
        return base * GOLD_DISCOUNT
    return base

どの入力に対しても、返る料金は整える前と同じです。学生の条件は、最後の return base の前に2行を足すだけで入りました。翌月に関数を開いた人は、上から順に読むだけで、どの条件で何円になるかを追えました。

コードは、書かれる回数より読まれる回数のほうがずっと多いものです。自分が手を止めた場所では、次にその関数を開く人もたいてい手を止めます。止まった場所を整えると、その後に読む全員の時間が減ります。

02止まった理由ごとに、当てる型が決まっています

整頓には、何度も使える小さな型があります。高橋さんが当てた型を含めて、止まった理由との対応を表にまとめます。

手が止まった理由当てる型
if の入れ子が深いガード節（例外の条件を冒頭で先に返す）
数字の意味が分からない説明定数（数字に名前を付ける）
式が長くて読めない説明変数（式の一部に名前を付ける）
処理の区切りが見えない空行で塊に分ける
塊が何をするか分からないヘルパー抽出（塊を名前付きの関数に出す）
使われていない削除する
理由が書かれていない説明コメントを書く

高橋さんの関数では、型を当てる順番にも意味がありました。最初にガード節で入れ子をほどくと、残った処理が1段の中に並びます。次に 0.8 に名前を付け、最後に使われていない引数 x を消しました。入れ子を先にほどいておくと、どの行がどの条件のときに動くのかが見えるので、残りの二つの型を当てる場所を探しやすくなります。

空行で塊に分ける型とヘルパー抽出は、もっと長い関数で使います。たとえば50行ある関数が、入力のチェック、金額の計算、メールの送信を続けて書いているなら、まず処理の区切りに空行を入れて三つの塊に分けます。塊が見えたら、それぞれを validate_request、calc_amount のような名前の関数に出します。名前を付けるときに迷うなら、その塊が一つのことをしていない可能性があるので、塊の切り方を見直します。

説明コメントは、コードから読み取れない理由を書くときに使います。「0.8 を掛ける」はコードを見れば分かるので、コメントに書く必要はありません。「ゴールド会員の割引率は年に一度、営業部が見直す」のように、なぜその値なのか、誰が決めるのかは、コードからは読み取れないのでコメントに残します。

型を一つ当てるたびに、テストか手元の確認で料金が変わっていないことを確かめます。一つの型は数分で終わるので、確かめる回数が増えても負担は小さく、何かがおかしいときは直前の一つを元に戻せば済みます。

03型を当てるときは、二つの場面で慎重になります

一つ目は、使われていないように見えるコードを消す場面です。関数の中で使われていない引数や、どこからも呼ばれていないように見える関数は、検索で見つからない場所から使われていることがあります。高橋さんが消した引数 x も、fee を呼ぶ側では値を渡していたので、呼び出し元の4か所から x を外す必要がありました。消す前には、次の手順で確かめます。

慎重になるもう一つの場面は、型を当てること自体が目的になる場面です。チームで決めている書き方とちがう形に整えると、次に読む人がかえって手を止めます。たとえばチームのコードが入れ子の if でそろっているなら、1つの関数だけをガード節にするより、チームで書き方を相談してから整えたほうが、読み手が迷いません。型は、自分が手を止めた理由を取り除くために当てます。止まらなかった場所を、表の型に合わせるために書き換える必要はありません。

04練習問題

次の関数は、在庫の数から発注するかどうかを決めます。読んで手が止まりそうな場所に、表のどの型を当てるかを答えてください。

def need_order(item):
    if item.active:
        if item.stock - item.held < 20:
            return True
    return False
  1. if が2段に入れ子になっている場所に当てる型はどれですか。
  2. 20 に当てる型はどれですか。名前の例も書いてください。
  3. item.stock - item.held に当てる型はどれですか。名前の例も書いてください。
  4. 三つの型を当てた後の関数を書いてください。返す値は元の関数と同じにします。

05解答と解説

  1. ガード節。使われていない商品は発注しないので、その条件を冒頭で先に返します。
  2. 説明定数。REORDER_POINT = 20 のように、発注を始める在庫の数だと分かる名前にします。
  3. 説明変数。available = item.stock - item.held のように、取り置き分を除いた、すぐ出せる数だと分かる名前にします。
  4. 次のようになります。
REORDER_POINT = 20

def need_order(item):
    if not item.active:
        return False
    available = item.stock - item.held
    return available < REORDER_POINT

最後の行は、if で True と False を返し分ける代わりに、比較の結果をそのまま返しています。これも動きを変えない整頓です。整える前と後で、使われていない商品・在庫が19の商品・在庫が20の商品の三つを試し、同じ値が返ることを確かめます。境目の20を試すのは、< と <= の書き間違いがあれば、境目の値で結果がずれるからです。

3行まとめ

  1. 自分がコードを読んで手を止めた場所は、次に読む人も手を止める場所なので、整える価値があります。
  2. 深い入れ子にはガード節、意味の分からない数字には説明定数、長い式には説明変数というように、止まった理由ごとに当てる型が決まっています。
  3. 使われていないように見えるコードは確かめてから消し、チームの書き方と食い違う形には整えません。
前へ「動きを変える」と「形を整える」は、別の作業として扱います 次へ整頓は小さく分けて出すほど、確かめやすくなります
