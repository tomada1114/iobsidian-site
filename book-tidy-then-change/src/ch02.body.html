整えてから変えるか、変えてから整えるか第2章 / 全7章

手が止まる理由に整頓の型を当てる

入れ子の条件や意味の分からない数字で手が止まったとき、どこを変えると読みやすくなるでしょうか。小さな料金計算にガード節や説明定数を当て、同じ結果を保つ方法を確かめます。型の選択と、呼び出し元まで調べる必要がある場面を練習します。

読了 約8分学習テキスト

この章で分かること

  • 読んでいて手が止まった場所を、なぜ整える価値があるのか
  • 止まった理由ごとに、どの整頓の型を当てればよいのか
  • 型を当てるとき、どこで慎重になればよいのか
  • 練習問題：短いコードに当てる型を選ぶ

01何が読み取れずに手が止まったか

料金の結果を保ちながら、読みにくい箇所の構造を小さく直します。どの型を使うかは、見た目の好みより、何が読み取れずに止まったかから選びます。

高橋さんは、会議室予約の料金計算に「学生は半額」という条件を加えます。次の関数は、会員がいないときや利用時間が正でないときに0を返し、ゴールド会員には割引を適用します。まず、この現在の動きをコードから読み取ります。

def fee(room, hours, member, x):
    if member is not None:
        if hours > 0:
            base = room.price * hours
            if member.rank == "gold":
                return base * 0.8
            return base
    return 0

高橋さんは3か所で手が止まりました。if が3段に入れ子になっていて、どの条件で0円になるのかがすぐには読めません。0.8 が何の数字かが書かれていません。引数の x は、関数の中で一度も使われていません。ここから先は、同じ場面を二通りに書きます。

条件をそのまま足すなら、どの条件の内側に置くかを理解する必要があります。高橋さんは15分かけて入れ子を読み、0.8をゴールド会員の割引だと考えました。学生の条件をさらに内側へ足すと、ifは4段になります。これでも正しく書ける可能性はありますが、次に読む人は同じ条件のまとまりをたどります。15分はこの架空の比較の設定で、どの読み手にも同じ時間がかかるという測定値ではありません。

先に整えるなら、「入れ子が深い」「0.8の意味が分からない」「xが使われていない」という、止まった理由を分けます。ガード節で先に0を返し、割引率へ名前を付け、引数の削除は呼び出し元も調べて行います。次のコードは、その三つを適用した状態です。

GOLD_DISCOUNT = 0.8

def fee(room, hours, member):
    if member is None:
        return 0
    if hours <= 0:
        return 0
    base = room.price * hours
    if member.rank == "gold":
        return base * GOLD_DISCOUNT
    return base

この例では、会員がいない場合と利用時間が正でない場合はどちらも0、通常会員は基礎料金、ゴールド会員はその0.8倍を返します。ガード節を前へ出しても、この四つの分岐の対応は変わりません。学生の条件は、この既存の分岐を読める形にした後で加える、別の振る舞いの変更です。学生とゴールドの両方に当たる場合にどちらの割引を使うかは、整頓の型だけでは決まらず、料金の仕様を確認する必要があります。

関数が繰り返し読まれるなら、条件を追いやすい構造には次の変更を助ける役割があります。ただし、手が止まった原因が、書き方ではなく料金の仕様を知らないことにある場合もあります。名前を増やすだけでは、その不明点は解決しません。書き方を整えるか、規則を確認して理由を残すかを分けると、型を当てる場所を絞れます。

02読みにくい理由に合う型を選ぶ

整頓には、何度も使える小さな型があります。高橋さんが当てた型を含めて、止まった理由との対応を表にまとめます。

手が止まった理由当てる型
if の入れ子が深いガード節（例外の条件を冒頭で先に返す）
数字の意味が分からない説明定数（数字に名前を付ける）
式が長くて読めない説明変数（式の一部に名前を付ける）
処理の区切りが見えない空行で塊に分ける
塊が何をするか分からないヘルパー抽出（塊を名前付きの関数に出す）
使われていない削除する
理由が書かれていない説明コメントを書く

高橋さんの関数では、型を当てる順番にも意味がありました。最初にガード節で入れ子をほどくと、残った処理が1段の中に並びます。次に 0.8 に名前を付け、最後に使われていない引数 x を消しました。入れ子を先にほどいておくと、どの行がどの条件のときに動くのかが見えるので、残りの二つの型を当てる場所を探しやすくなります。

空行で塊に分ける型とヘルパー抽出は、もっと長い関数で使います。たとえば50行ある関数が、入力のチェック、金額の計算、メールの送信を続けて書いているなら、まず処理の区切りに空行を入れて三つの塊に分けます。塊が見えたら、それぞれを validate_request、calc_amount のような名前の関数に出します。名前を付けるときに迷うなら、その塊が一つのことをしていない可能性があるので、塊の切り方を見直します。

説明コメントは、コードから読み取れない理由を書くときに使います。「0.8 を掛ける」はコードを見れば分かるので、コメントに書く必要はありません。「ゴールド会員の割引率は年に一度、営業部が見直す」のように、なぜその値なのか、誰が決めるのかは、コードからは読み取れないのでコメントに残します。

型を一つ当てるたびに、料金が変わっていないことを確かめます。小さく分けていれば、失敗したときに直前の操作を先に調べられます。ただし、名前の変更でも呼び出し元が多ければ時間はかかります。操作の行数だけでなく、同じ結果を確かめる範囲が小さいことも、整頓の大きさを判断する条件です。

03削除の確認と、型を使いすぎる限界

一つ目は、使われていないように見えるコードを消す場面です。関数の中で使われていない引数や、どこからも呼ばれていないように見える関数は、検索で見つからない場所から使われていることがあります。高橋さんが消した引数 x も、fee を呼ぶ側では値を渡していたので、呼び出し元の4か所から x を外す必要がありました。消す前には、次の手順で確かめます。

記録がないことだけで、将来も呼ばれないとは決まりません。ログが実際に取れているか、月末やまれな操作を含む期間を見たか、別のプログラムが名前で呼ぶ契約がないかを確認します。観察できない入口が残るなら、削除を急がず担当者へ確かめます。

もう一つ慎重になるのは、型を当てること自体が目的になるときです。チームの書き方と異なる形を一つの関数だけに入れると、次に読む人が別の流儀を覚える必要が出ます。ガード節を使うこと自体の賛否より、どの条件が読みにくく、どう直すと共通に読めるかを話します。止まらなかった場所まで表の型に合わせる必要はありません。

04練習問題

次の関数は、在庫の数から発注するかどうかを決めます。読んで手が止まりそうな場所に、表のどの型を当てるかを答えてください。

def need_order(item):
    if item.active:
        if item.stock - item.held < 20:
            return True
    return False
  1. if が2段に入れ子になっている場所に当てる型はどれですか。
  2. 20 に当てる型はどれですか。名前の例も書いてください。
  3. item.stock - item.held に当てる型はどれですか。名前の例も書いてください。
  4. 三つの型を当てた後の関数を書いてください。返す値は元の関数と同じにします。

05解答と解説

  1. ガード節。使われていない商品は発注しないので、その条件を冒頭で先に返します。
  2. 説明定数。REORDER_POINT = 20 のように、発注を始める在庫の数だと分かる名前にします。
  3. 説明変数。available = item.stock - item.held のように、取り置き分を除いた、すぐ出せる数だと分かる名前にします。
  4. 次のようになります。
REORDER_POINT = 20

def need_order(item):
    if not item.active:
        return False
    available = item.stock - item.held
    return available < REORDER_POINT

最後の行は、if で True と False を返し分ける代わりに、比較の結果をそのまま返しています。これも動きを変えない整頓です。整える前と後で、使われていない商品・在庫から確保分を引いた残りが19の商品・20の商品の三つを試し、同じ値が返ることを確かめます。境目の20を試すのは、< と <= の書き間違いがあれば、境目の値で結果がずれるからです。

3行まとめ

  1. 手が止まった原因を、条件の追いにくさ、名前の不足、仕様の不明などに分けると、整える対象を絞れます。
  2. 深い入れ子にはガード節、意味の分からない数字には説明定数、長い式には説明変数というように、止まった理由ごとに当てる型が決まっています。
  3. 使われていないように見えるコードは確かめてから消し、チームの書き方と食い違う形には整えません。
