Who stops a bad import when nobody is watching?

After this page you can explain how a monorepo with workspace packages turns architecture boundaries into checks a machine runs. You can also say why that matters more when AI coding agents write much of the code.

01One repository or several

A contract change can affect the API, web client and shared schema at once. A monorepo lets that coordinated change appear in one commit and review, under one set of checks. Separate repositories require versions and release ordering.

Separate repositories can still provide independent releases, permissions and toolchains. Swift and Kotlin clients may justify that separation. Repository layout should follow which components change together and who owns them, rather than indicate how serious the product is.

02Packages with explicit surfaces

Quickturn uses pnpm workspaces, with each package declaring dependencies in its manifest. Package exports expose an intended public entry point. Together they limit accidental coupling, though relative imports and configuration still need boundary checks.

Packages expose TypeScript source rather than separate prebuilt output. Vite, tests or the API runtime compile or handle it for their own use. Node's type stripping supports a subset of TypeScript; code must stay within the chosen runtime's supported syntax and resolution rules.

The domain has no adapter dependencies. Application code depends on the domain, adapters implement application interfaces, and HTTP contracts own boundary schemas. Web and native clients use HTTP contracts and generated client types rather than importing server internals.

03Edges enforced twice

Lint uses an allowed-edge table: domain imports no other workspace package, application imports domain, adapters import application and domain, and contracts use Zod. An independent test examines actual imports and manifests. Removing one check leaves the other enforcing the boundary.

Manifests control package reachability, while boundary rules control permitted direction and file-level relationships. A useful error identifies the forbidden edge and points to the application-owned port. That helps both a developer and a coding agent repair the design.

Nx offers boundary checks; Turborepo focuses on task orchestration and caching. Quickturn's short builds and source packages do not yet justify adding a task system solely for caching.

04Is it worth the config?

Workspace manifests, lint configuration and an import-graph test all require maintenance. A new package must declare its intended edges. That small delay is the moment to decide what it may depend on.

The benefit grows when many people or agents change code. Written guidance can be missed; a forbidden import that produces a failing check has a concrete consequence. An architectural fitness function tests a design property rather than a feature.

A small project may need only a modest lint policy. Independent checks are useful when boundaries face frequent edits, provided the team can keep those checks understandable and current.

Summary in three lines

  1. One repository lets a contract and its clients change in one commit, when one team changes them together.
  2. Workspace dependencies and a single exported entry file make each package's public surface explicit.
  3. Lint and a graph test both check the allowed edges, so a wrong import fails the build, whoever wrote it.
