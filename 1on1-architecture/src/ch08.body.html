Where does the logic go, if not in the handler?

A learner who has finished today's portion should receive an extra round. Testing that decision should not require an HTTP handler or a database.

01Load, decide, commit

Suppose the learner has already completed today's portion. Starting another round should create an “extra” round rather than another “today” round. That is a product decision, not an HTTP or database concern. Putting it inside the handler makes its test depend on mocked infrastructure.

Quickturn's command instead loads required values through application-owned ports, calls a pure domain decision function, and commits its changes. Time and IDs are supplied values. The decision returns either an expected failure or the changes and response.

This is a functional core with an imperative shell. Reads and writes stay around the edge; rules operate on ordinary inputs. A direct test can pass a completed portion and assert an extra round without specifying which storage calls occurred.

02Two kinds of failure

A missing round, closed round or shortage of cards is an expected outcome represented by a Result value. The API maps it to a stable error code such as ERR_ROUND_CLOSED. Unexpected bugs are treated separately. Infrastructure failures also need handling in the shell rather than pretending they are domain decisions.

Time is another explicit input. A practice day depends on the learner's time zone and day-boundary hour, not the Lambda process's default UTC zone. Quickturn starts a practice day at 4 a.m. local time. Supplying those values makes the rule both correct for the learner and repeatable in tests.

03One shape, many callers

A command consists of validated data and a request context identifying the actor. The same command can be called from HTTP, a grading worker or an agent tool. The entry adapter changes, while the rule stays in the domain.

Quickturn distinguishes a learner, a system job and an agent with explicit grants. Authorization examines that context before an operation proceeds. An agent's ability to reach a tool does not independently grant access to the learner's data. A future entry point can reuse the command only if it supplies a trusted actor context and satisfies the same checks.

04What it costs

A pure decision cannot fetch extra data halfway through. The shell must load its inputs first, sometimes including data that only one branch needs. Passing in a fetch callback would allow conditional reads, but it would also reintroduce I/O and failure into the core.

The separation takes practice, and it does not remove the need for integration tests. Store contracts check adapter behavior, and selected end-to-end tests exercise the whole path. For trivial CRUD, a separate decision function may add no value.

The related “impure–pure–impure sandwich” makes sense when the middle contains rules worth protecting. It is a way to locate complexity, not a requirement to split every function into three files.

Summary in three lines

  1. Keep decisions in a pure decide function, and let a thin shell load and commit around it.
  2. Return expected failures as values, handle unexpected faults separately, and supply time and time zones explicitly.
  3. One command shape serves HTTP, workers and agent tools; the cost is loading up front and testing the shell.
