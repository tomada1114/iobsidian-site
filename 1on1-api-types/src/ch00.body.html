Engineering Readers: API and TypeScript

A request can pass through checked code and still carry invalid data. An older app or a retry can also challenge an otherwise sound API. These chapters examine what types, boundaries and contracts can protect across those conditions.

11 pagesAbout 44 minEnglish, B2 · explanatory prose

The example application

Quickturn is a fictional language-learning application. A learner answers a card before a timer ends, then reviews progress and mistakes. Its web, iOS and Android clients share an API.

These chapters use that application to explain concrete engineering choices, their costs and the conditions that would justify a different design. Each chapter stands on its own; no conversation or earlier chapter is needed.

How the pages fit together

The pages

  1. If types vanish at runtime, what are they for? — Types check our code; outside data stays unknown until checked.
  2. Which compiler flags change how I write code? — strict is a floor, and a loosened gate stops being one.
  3. Why not just add another boolean flag? — A discriminated union describes valid alternatives inside checked code.
  4. Should a function throw, or return its failure? — Return expected failures with a code, and handle unexpected failures separately.
  5. Trust nothing at the boundary: parse it once — Parse outside data once at the edge into a precise type.
  6. REST, GraphQL or RPC: how do you choose? — The API style follows the clients and how they read data.
  7. Where does the API contract actually live? — Shared schemas feed documents and client types; tests check generation and behavior.
  8. How do you change an API without breaking old apps? — Stable codes, additive changes, and deprecation before removal.
  9. What if the same request arrives twice? — Client-made ids and conditional writes make repeats harmless.
  10. Can an app work offline if the server owns the rules? — The client records facts; the server applies the rules on arrival.
  11. Why a static SPA instead of server rendering? — A static client suits Quickturn's signed-in screens and shared API, with a first-load cost.
