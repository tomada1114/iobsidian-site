コードの書き方を変えるコンパイラオプションはどれか

配列の要素の型が正確に見えても、インデックスで取り出した値は存在しないことがあります。値がない場合のうち、どれをコードで扱わなければならないかは、コンパイラオプションで決まります。

01strict に含まれないもの

strict オプションは、厳密な null チェックや暗黙の any の禁止など、一連のチェックをまとめて有効にします。ただし、安全性を高めるオプションがすべて含まれるわけではありません。Quickturn では、インデックスアクセス、省略可能なフィールド、インデックスシグネチャ、import の構文に関する四つのオプションを追加しています。

これらのオプションは、それぞれ別の種類の失敗に対応します。書式を指示するためのものではなく、値が欠けているかもしれない箇所や、変換後に消える型の import を明示させるためのものです。

noUncheckedIndexedAccess
arr[i] が undefined になりうるものとして扱います。配列の末尾を越えた読み取りを防ぎます。
exactOptionalPropertyTypes
「フィールドがない」と「undefined が入っている」を区別します。誤ってフィールドを消してしまうミスを防ぎます。
noPropertyAccessFromIndexSignature
マップの参照にブラケット記法を求めます。フィールドへのアクセスに見えるマップ参照を防ぎます。
verbatimModuleSyntax
import を書いたとおりに出力します。意図せずモジュールが実行される事態を防ぎます。

コンパイラ設定を共有すると、すべてのパッケージが同じ前提に立てます。以下の例では、その前提が日々のコードで何を変えるのかを説明します。

02一つのオプションが一つのバグを防ぐ

noUncheckedIndexedAccess を有効にすると、配列や辞書を参照した結果は undefined になりうるものとして扱われます。長さを確かめても、別に書いたインデックスアクセスの式に値があることまでは、一般には保証されません。要素をいったん変数に読み出し、その値を絞り込んでから使います。

exactOptionalPropertyTypes は、省略可能なフィールドが存在しない状態と、明示的に undefined を代入した状態を区別します（型が undefined を含む場合を除きます）。更新用のオブジェクトで役に立ちますが、JSON は undefined の値を出力しないので、フィールドを空にする方法は API 側で別に定める必要があります。

noPropertyAccessFromIndexSignature は、インデックスシグネチャだけで定義されたフィールドにブラケット記法を求めます。verbatimModuleSyntax は型だけの import を明示させます。import を消してよいかをコンパイラが推測することも、モジュールの副作用が意図せず起きることもなくなります。

const first = cards[0];
if (first === undefined) return noCards();
first.id; // first: Card

type Settings = { sound?: boolean };
const a: Settings = {};                 // OK：フィールドなし
const b: Settings = { sound: undefined }; // エラー

03オプションのコストとゲート

既存のコードベースでこれらのオプションを有効にすると、移行の作業が発生します。値がない場合のチェック、フォールバック、ライブラリとの非互換に対応しなければなりません。Quickturn は長く使うコードのためにそのコストを受け入れ、CI で型チェックを必須にしています。

あるとき、生成したクライアントが省略可能プロパティの厳密なチェックで失敗しました。選択肢は、その生成物についてだけ設定を緩めるか、生成する内容を変えるかの二つでした。

Quickturn は型だけを生成し、satisfies で検査する小さな fetch モジュールを手で保守しています。satisfies は、値の推論された型を置き換えずに、互換性だけを検査する演算子です。このモジュールには保守の手間がかかるので、互換性のあるジェネレーターが出れば判断を見直す価値があります。

インデックスの読み取りでエラーが出たら、パッケージ全体のチェックを外すのではなく、値がない場合を扱って直すのが基本です。例外を認めるなら、どの保護を失うのかを理解したうえで決めます。

3行まとめ

  1. strict は最低ラインです。noUncheckedIndexedAccess や exactOptionalPropertyTypes は、別に有効にするオプションです。
  2. 追加のオプションは、それぞれ一種類のミスを実行前に検出します。その代わり、日々のコードに書くチェックは増えます。
  3. Quickturn は型を生成し、小さな fetch モジュールを保守することでチェックを維持しています。互換性のあるジェネレーターが出れば、この判断は変わりえます。
