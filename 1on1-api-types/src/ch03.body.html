Why not just add another boolean flag?

A system flag can appear without a job name, or beside an unrelated learner ID. Optional fields allow combinations that the actor model needs to rule out.

01A bag of flags

An actor represented by optional learner ID, system flag, job name and on-behalf-of ID permits many meaningless combinations. A system flag alone does not say which job is running or which learner it serves. Every reader would need to reconstruct those constraints.

“Make illegal states unrepresentable” means designing the type around valid alternatives. This improves the model inside checked code; runtime input still requires parsing, and unsafe assertions can bypass it.

type Actor = {
  learnerId?: string;
  isSystem?: boolean;
  jobName?: string;
  onBehalfOf?: string;
};

02One tag, exact fields

Quickturn's actor is a discriminated union. Its kind identifies a learner, a system job or an agent, and each member requires the fields appropriate to that case. Checking the tag narrows the available fields.

An agent actor names one learner and carries operation grants. An as const list supplies runtime operation names. Its indexed access type, (typeof LIST)[number], gives the corresponding static union. The type describes the grants; authorization must still enforce them.

type Actor =
  | { kind: "learner"; learnerId: LearnerId }
  | { kind: "system"; job: SystemJob;
      onBehalfOf: LearnerId }
  | { kind: "agent"; onBehalfOf: LearnerId;
      grants: readonly OperationKind[] };

03Exhaustive, and no enums

An exhaustive switch handles every union member. Assigning the remaining value to never makes a newly added case fail compilation. An exhaustiveness lint rule can serve the same purpose.

switch (actor.kind) {
  case "learner": return actor.learnerId;
  case "system":  return actor.onBehalfOf;
  case "agent":   return actor.onBehalfOf;
  default: {
    const unreachable: never = actor;
    return unreachable;
  }
}

A catch-all default inside controlled code can conceal missing behavior. Across a public API, however, an installed client may receive an alternative added after it shipped, so a safe fallback is necessary.

Quickturn uses string unions instead of enums because its runtime relies on erasable TypeScript syntax. Enums can require JavaScript output that a type-stripping runtime does not provide. Exact strings also map directly to JSON.

04When a union is the wrong shape

A union is most helpful when cases have different required fields. If nearly every field is shared, use a common shape or base rather than repeat the entire object. A very large union may indicate that several independent concepts have been mixed together.

Parse external data into the union before relying on narrowing. Inside one controlled version, use exhaustive handling; across independently deployed clients, allow unknown variants safely. An actor type helps expose missing identity or grants, but the server must derive identity from trusted authentication and check permissions.

Summary in three lines

  1. A discriminated union requires the fields for each alternative inside checked code; external input still needs parsing.
  2. Exhaustive checks expose missing switch cases; a catch-all branch can conceal behavior that still needs to be added.
  3. Inside your code stay exhaustive, but clients of a public API keep a default branch for new cases.
