If types vanish at runtime, what are they for?

After this page you can explain what TypeScript checks and what it never checks. You can also say where a runtime check must go, and why a cast is not one.

01Shapes, not names

TypeScript compares the structure of values, rather than requiring a declared class or interface name. An object with a learnerId field can satisfy HasLearner even if it never names that interface. This is structural typing.

Inference supplies many local types, so explicit annotations are most useful at shared boundaries such as function parameters and exported return values. Those annotations state the promises other code relies on.

interface HasLearner { learnerId: string }

function greet(x: HasLearner) { return x.learnerId }

// this object never mentions HasLearner
const req = { learnerId: "L1", deckSize: 10 };
greet(req); // compiles: the shape fits

02Unions and narrowing

A union describes alternatives: string | undefined, or exact strings such as "first" | "retry". A check narrows the set of possible values in a branch. After an early return for undefined, the remaining value can be used as a string.

function label(name: string | undefined) {
  // name: string | undefined
  if (name === undefined) {
    return "Guest"; // name: undefined
  }
  // name: string
  return name.toUpperCase();
}

Narrowing lets code and types describe the same decision. With discriminated alternatives and an exhaustive check, adding a new round kind can expose handlers that have not considered it. The compiler helps inside the program, where it has evidence about a value.

03What types cannot do

Type annotations and assertions are erased when TypeScript becomes JavaScript. Writing as StartRoundRequest after reading JSON does not inspect a request. It only asks the compiler to trust the programmer.

If outside data contains deckSize: "ten", the assertion does not turn it into a number. Treat external values as unknown, which prevents their use until a runtime check establishes their shape. any removes that protection.

Quickturn limits body size, parses JSON and checks it against a schema before a command runs. Invalid input receives a stable bad-request code. Branded IDs add another compile-time distinction between values such as learner and card IDs, which would otherwise both look like strings.

Static checks add no runtime validation. Runtime parsing costs some code and time, so place it at actual trust boundaries.

04Beyond Quickturn

A language-model response is outside data too. Asking for a score and reason does not make a parsed reply a GradeResult. A cast could hide score: "high" until unrelated downstream code fails.

Quickturn asks for structured output and still parses the reply. Requests, uploaded files, persisted browser data and model replies all cross boundaries where static types alone cannot establish trust.

Summary in three lines

  1. TypeScript checks shapes, infers most types and narrows unions as your code checks them.
  2. Every type is erased at build time, so as and any check nothing while the program runs.
  3. Treat anything from outside, including a model's reply, as unknown and check it once at the edge.
