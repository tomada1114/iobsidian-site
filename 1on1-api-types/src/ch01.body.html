01名前ではなく形で比べる

TypeScript は、宣言されたクラス名やインターフェース名ではなく、値の構造を比べます。learnerId フィールドを持つオブジェクトなら、HasLearner という名前に一度も触れていなくても、そのインターフェースを満たせます。これを構造的型付けと呼びます。

ローカルな値の型の多くは推論で決まります。明示的な型注釈が役立つのは、関数の引数や export する戻り値のように、他のコードと共有する境界です。そこに書いた注釈が、他のコードが頼りにする約束になります。

interface HasLearner { learnerId: string }

function greet(x: HasLearner) { return x.learnerId }

// このオブジェクトは HasLearner に一度も触れていない
const req = { learnerId: "L1", deckSize: 10 };
greet(req); // コンパイルが通る：形が合っている

02ユニオン型と絞り込み

ユニオン型は選択肢を表します。string | undefined や、"first" | "retry" のような特定の文字列の組み合わせがその例です。分岐の中で値を検査すると、取りうる値の集合が絞り込まれます。undefined のときに早期 return すれば、残った値は文字列として扱えます。

function label(name: string | undefined) {
  // name: string | undefined
  if (name === undefined) {
    return "Guest"; // name: undefined
  }
  // name: string
  return name.toUpperCase();
}

絞り込みを使うと、コードと型が同じ判断を表すようになります。判別可能な選択肢と網羅性チェックを組み合わせれば、ラウンドの種類を新しく追加したとき、まだそれを考慮していないハンドラーが見つかります。コンパイラが助けになるのは、値についての根拠を持てるプログラムの内側です。

03型にできないこと

TypeScript を JavaScript に変換するとき、型注釈と型アサーションは消えます。JSON を読んだあとに as StartRoundRequest と書いても、リクエストの中身は検査されません。プログラマーを信じるよう、コンパイラに頼んでいるだけです。

外部データに deckSize: "ten" が含まれていても、アサーションで数値になるわけではありません。外から来た値は unknown として扱います。unknown の値は、実行時の検査で形が確かめられるまで使えません。any にすると、この保護がなくなります。

Quickturn は、コマンドを実行する前にボディのサイズを制限し、JSON をパースし、スキーマで検査します。不正な入力には、不正なリクエストを表す決まったエラーコードを返します。さらにブランド型を使うと、学習者 ID とカード ID のように、どちらもただの文字列に見える値をコンパイル時に区別できます。

静的な検査は、実行時の検証を何も追加しません。実行時のパースにはコードと処理時間のコストがかかるので、本当に信頼の境界になっている場所に置きます。

04モデルの応答も外部データ

言語モデルの応答も外部データです。スコアと理由を返すよう頼んでも、パースした応答が GradeResult になる保証はありません。キャストで済ませると、score: "high" のような値が気づかれないまま処理が進み、関係のない下流のコードで初めて失敗することがあります。

Quickturn は構造化出力を指定したうえで、それでも応答をパースします。リクエスト、アップロードされたファイル、ブラウザに保存したデータ、モデルの応答は、どれも静的な型だけでは信頼を確立できない境界を越えてきます。

3行まとめ

  1. TypeScript は形で型を比べ、ほとんどの型を推論し、コードの検査に合わせてユニオン型を絞り込みます。
  2. 型はビルド時にすべて消えるため、as や any はプログラムの実行中に何も検査しません。
  3. モデルの応答を含め、外から来るものはすべて unknown として扱い、入口で一度だけ検査します。
