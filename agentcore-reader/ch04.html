Why let the model run the loop?

After this page you can explain what model-driven means in Strands Agents, and name the six layers of its harness. You can also say how agents are combined, and how Strands differs from a graph-based framework.

About 8 min readPairing at Leo's desk

In this page

  • What does model-driven mean?
  • What are the six layers of the harness?
  • How are agents combined?
  • How is this different from LangGraph?

Leo's desk. A minimal agent is open on his screen, and it looks far too short.

01Model-driven

L

Leo: This is the whole agent? I'm used to writing every step myself: call A, check a condition, then call B.

M

Maya: And here?

L

Leo: Here I can't find the steps at all.

M

Maya: There aren't any. Strands Agents is model-driven. You give the model a system prompt and a list of tools, and the model decides what to do next.

L

Leo: So the model runs the loop itself. That's what makes it an agent.

M

Maya: Right. AWS recommends Strands and maintains two versions, Python and TypeScript. Here's the minimal example, in Python:

from strands import Agent, tool

@tool
def get_weather(
    city: str) -> str:
  """Return the weather
  for the given city."""
  return lookup(city)

agent = Agent(
  model="...",
  tools=[get_weather],
  system_prompt=
    "You are a weather guide.")
agent("Weather in Tokyo?")
L

Leo: That's it? A model, some tools and a prompt, passed to one class?

M

Maya: And the loop is ready to run. A tool is a normal function with @tool above it.

L

Leo: How does the model know what the tool does?

M

Maya: The function name, the argument types and the docstring become its instructions. You don't write a separate spec file.

L

Leo: So the docstring actually matters.

M

Maya: More than most comments you'll ever write. The model reads it every time.

L

Leo: So a vague docstring means the model guesses when to call the tool.

M

Maya: Or calls the wrong one. "Return the weather for the given city" tells it exactly when this tool helps.

L

Leo: Does it only work with Bedrock?

M

Maya: Bedrock is the default model provider. You can also choose Anthropic, OpenAI, Ollama or LiteLLM.

L

Leo: And the MCP tools from my weekend agent?

M

Maya: Strands can act as an MCP client. Tools from an outside MCP server are passed in just like your own functions.

L

Leo: And our tutor?

M

Maya: It's written in TypeScript, with the Strands Agents TypeScript SDK.

02Six layers of control

L

Leo: But if the model decides everything, where's my control? I can't just hope.

M

Maya: That's the harness. The official Strands Workshop lists six layers inside it.

L

Leo: The loop is one, I guess.

M

Maya: The loop is the center: think, use a tool, look at the result. Then the tools: normal functions, or outside tools through MCP.

L

Leo: The model picks, and the harness runs them.

M

Maya: Right. Next come hooks. They step into events in the loop, such as before and after a tool call.

L

Leo: What would I use a hook for?

M

Maya: To block a dangerous action, write a call to a log, or change the arguments.

L

Leo: And skills?

M

Maya: Instructions the agent loads only when needed. Most of the time, the model sees only a skill's name and a short description.

L

Leo: And loads the full text when it uses it.

M

Maya: Yes. Then steering: it adds new instructions to a running agent, based on the situation, to adjust its direction.

L

Leo: And the last one?

M

Maya: The session. It saves the conversation's state so you can start it again later.

L

Leo: What if the conversation gets too long?

M

Maya: A conversation manager decides what to drop or summarize.

L

Leo: Why would skills load only when needed? Why not give the model everything at the start?

M

Maya: Every instruction takes space in the model's context and costs tokens on every turn. A short description is enough until the skill is actually used.

L

Leo: So the inner layers deal with one tool call, and the outer ones with the whole run.

M

Maya: That's the way to read it. And it helps you choose where a rule belongs.

L

Leo: Like what?

M

Maya: Say "don't handle personal data." Written in the system prompt, it's only a request.

L

Leo: And the model might misread it.

M

Maya: Or a clever input pushes it past the rule. For rules you truly need to enforce, use the harness side: a hook, or the Policy part. Those stop the action in code.

L

Leo: So control means choosing the layer, not writing every step.

03Combining agents

M

Maya: Now, one agent is rarely the end. Strands gives three ways to combine them.

L

Leo: What's the simplest?

M

Maya: Calling an agent as a tool. From the parent's view, the child looks like a single function call.

L

Leo: And the others?

M

Maya: A Swarm is a group of equal agents that hand work to each other. When one decides a task is too hard, it passes the conversation on.

L

Leo: No boss in a Swarm, then.

M

Maya: No. The third is a Graph. Work moves between agents along a path you set in advance.

L

Leo: For when I want to fix the order myself.

M

Maya: Right. And when agents talk across systems or teams, Strands supports A2A. Another team's agent can call one built inside your company.

L

Leo: So the three forms plus A2A for crossing team lines.

M

Maya: And the first form is usually enough. Try an agent as a tool before you use a Swarm.

L

Leo: Because a Swarm is harder to follow?

M

Maya: Each hand-off is another decision the model makes. It's harder to predict who ends up answering.

04Model-driven or graph-driven

M

Maya: You mentioned graphs earlier. That's LangGraph's design.

L

Leo: I've used it. You write state changes as an explicit graph.

M

Maya: And you decide in code which node comes after which. That makes behavior easier to predict, even with complex branches.

L

Leo: While Strands lets the model make that decision.

M

Maya: That's the main difference. Here it is side by side.

L

Leo: So which one should I pick?

M

Maya: It's a choice between two design styles. AgentCore doesn't require a framework, so either runs the same way on Runtime.

L

Leo: If predictability matters most, a graph. If the path can't be known in advance, model-driven.

M

Maya: And inside Strands, a Graph gives you fixed order where you need it.

L

Leo: So I don't have to choose one style for the whole system.

M

Maya: No. A fixed part can be a Graph, and the open part can stay model-driven.

05Leo explains it back

M

Maya: You started by asking where the steps were. Where are they?

L

Leo: There are none to write. The model plans the steps, from the tools and the system prompt.

L

Leo: My control comes from the harness layers: loop, tools, hooks, skills, steering and session.

L

Leo: A rule that must hold goes in a hook or in Policy, not in the prompt.

M

Maya: And when one agent isn't enough?

L

Leo: Agents combine as tools, as a Swarm or as a Graph, and A2A crosses team lines.

M

Maya: You left out the choice against a graph. LangGraph is easier to predict, and model-driven handles paths you can't write in advance; both run on Runtime.

Summary in three lines

  1. Strands Agents is model-driven: the model decides the steps from tools and a system prompt.
  2. The harness has six layers: loop, tools, hooks, skills, steering and session.
  3. Agents combine as tools, a Swarm or a Graph; Runtime runs any framework the same way.
