Map of AgentCore: what does it do for you?

In this chapter, we look at the full picture of Amazon Bedrock AgentCore, the set of parts that AWS built to run an agent's harness in production. There are about eight parts. You can use each one alone, or combine them. First, let's build a map in our heads.

01Parts that support the agent, not the agent itself

You write the agent itself in code. This includes the harness that runs the loop, and the model it uses. Amazon Bedrock AgentCore is not a service for building that agent. It is a service that gives you the support features you need to run the agent in production, such as authentication, memory, and monitoring.

Each part is a separate AWS feature. You can call it from an agent built with any framework, such as Strands, LangGraph, or CrewAI, and with any model. AgentCore itself is not tied to one way of writing code.

Another important point: you only need to use the parts you need. For example, some teams use Memory without Runtime, or add Gateway first, before anything else. You do not need to use every part together.

02All the parts at a glance

Here are the eight parts. For each one, we give a short description and an analogy. Later chapters cover each part in detail, as shown in the table.

Analogy: the new employee

When a company places a new employee (the LLM), it does not rely on that person's skill alone. It also gives them a seat, a work notebook, a toolbox front desk, an ID badge, rules to follow, a daily report, and a yearly performance review. The AgentCore parts match this whole set.

Two more topics are not in the table above. Payments are covered in an official Deep Dive module called "Agents that transact." It looks at cases where an agent makes a payment. We will not go deep here.

The AgentCore CLI is where development starts. It is a development tool for creating an agent, running it locally, and deploying it, all with commands. It replaces the old Starter Toolkit.

Another word you often see in the official courses is Harness. Some Labs in the official Workshop, and some Tracks in the official Deep Dive, have a module named "Harness." This is the same idea: the program outside the LLM that runs the loop. Different courses describe this in different ways, so we will not state exactly what AgentCore itself provides for it.

03A diagram of how the parts fit together

Let's arrange these parts in the order a request flows through them. The colors in the diagram show four groups: blue is for thinking (Runtime, Memory), green is for acting (Gateway, Code Interpreter, Browser), purple is for guarding (Identity, Policy), and yellow-brown is for running the whole cycle (Observability, Evaluations).

As the diagram shows, each part has its own job: Runtime is the place, Memory is the memory, and Gateway is the toolbox front desk. The roles do not overlap. Each part handles one concern, so you can add only the parts you need.

04What the order of adding parts teaches us

The official Phase 1 workshop, "Getting Started with Amazon Bedrock AgentCore," shows a real example of the order to add these parts. It builds one customer support agent, and adds production features to it, one at a time.

This order of adding parts is the same order you need when moving from a PoC to production. You start with something that runs, then strengthen it step by step with memory, tools, authentication, evaluation, and control.

05The official courses follow two phases

The official AgentCore courses are split into two main phases. Phase 1, "Getting Started," is the 9 labs we just saw, done in order. It is for people who are new to AgentCore.

Phase 2, "Diving Deep," has 8 modules that you can study in any order, working together with Claude Code. Since there is no fixed order, you can go deep into the part you need first. This reader's roadmap points you to both phases, depending on the situation.

06Pricing: pay for each part you use

AgentCore uses pay-per-use pricing. You only pay for what you use. Parts like Runtime, Memory, and Gateway are each billed separately, and you pay nothing for a part you do not use. The exact prices change often, so this reader will not give numbers here. Just remember the idea.

Where companies get stuck

If you built these eight parts yourself, even just separating each session's environment, storing login details safely, and collecting traces of every call would each take weeks of work. Many companies stop after the PoC stage, not because the agent is not smart enough, but because they do not have the resources to build all of this support themselves. The value of AgentCore is that it already has these parts ready for you.
