When is it really an agent?

A grading call follows known steps, while a tutor chooses what to investigate. The difference lies in who selects the next action and who limits it.

About 8 min readThe whiteboard room

The whiteboard room. Leo has just joined the team that owns Quickturn's tutor agent.

01Three levels

L

Leo: So I'm on the agent team now. Our grading feature calls an LLM, so that's an agent too, right?

M

Maya: What does grading do, step by step?

L

Leo: It sends the learner's answer and a rubric to the model. The model returns a grade.

M

Maya: Who decides what happens next?

L

Leo: Our code. It stores the grade and moves on.

M

Maya: Consider three designs with different amounts of model control. They are alternatives for a task, rather than stages every feature must pass through.

L

Leo: What's the first level?

M

Maya: Call it once for a bounded task, such as classifying this question. The surrounding code still checks and uses the result.

L

Leo: One input, one output.

M

Maya: The second level calls the LLM several times, in steps a person designed. That's a workflow.

L

Leo: Like what?

M

Maya: Classify the question, write an answer with a different prompt for each type, then check it for banned words. The code decides the order. The LLM only does the work inside each step.

L

Leo: And the third level is the agent.

M

Maya: Right. Here the LLM decides the steps itself. It looks at the goal and a list of tools it can use.

L

Leo: What's a tool, exactly?

M

Maya: An action the agent can call, like a search or a database lookup. The LLM chooses what to do next, each time.

L

Leo: "Search for the customer first. Not enough, so check the orders too. Now I can answer."

M

Maya: The model chooses the next action rather than following a fixed sequence. The harness also needs stopping limits for time, turns and spending.

L

Leo: So grading is the first level: one call, inside steps our code fixes.

M

Maya: Close to it. Our code runs the same steps every time, so it's certainly not an agent. The tutor is an agent. It decides whether to look up the learner's weak points, explain, or ask a question.

L

Leo: Then going down the ladder is better, isn't it? More intelligent.

M

Maya: Extra model choices can add calls and variable paths to a fixed task. Compare that cost with a workflow before adding autonomy.

L

Leo: So the skill is choosing the level.

M

Maya: Deciding what to fix in code and what to leave to the LLM is the real skill in good design.

02Inside the agent loop

L

Leo: What does the loop actually look like?

M

Maya: It's very simple. You give the LLM the user's request, and a list of tools: each one's name, what it does, and its arguments.

L

Leo: And the LLM answers.

M

Maya: Or it asks to call a tool with certain arguments. If it asks, the program runs that tool.

L

Leo: Then what?

M

Maya: The harness adds the result to the conversation and sends it back. It stops on an answer, a failure or a configured limit.

L

Leo: So the LLM calls the API itself?

M

Maya: The model proposes a tool call with arguments. The receiving program decides whether to execute it and calls the API.

L

Leo: What do you call that program?

M

Maya: A harness, like the straps and gear you put on a horse. It runs the loop, calls the tools and keeps the conversation history.

L

Leo: Does the harness only run the loop?

M

Maya: It does more. It can stop a dangerous action before a tool runs. It can summarize old messages when a conversation gets too long, and it records what happens.

L

Leo: That sounds like most of the real work.

M

Maya: Often it is. Here's a picture that helps. The LLM is a new employee who thinks fast, but can't leave the desk or make calls.

L

Leo: So it writes a note: "I want to see this customer's orders."

M

Maya: And the colleague at the next desk, the harness, uses the system and hands back the result. The employee reads it and writes the next note.

L

Leo: And that exchange is the agent.

M

Maya: That's all an agent is.

03Workflow patterns first

L

Leo: So before building an agent, what should I check?

M

Maya: Whether a workflow pattern can do the job. Several have common names.

L

Leo: Such as?

M

Maya: Chaining uses one step's output as the next step's input. Draft, then translate, then proofread.

L

Leo: And routing?

M

Maya: Classify first, then send each type to a different process. Billing, technical or cancellation questions, say.

L

Leo: What about parallel?

M

Maya: Send the same input to several processes at once, then combine the results. Reviewing something from several angles, for example.

L

Leo: And for bigger jobs?

M

Maya: Orchestrator and workers. A parent LLM splits the work and gives pieces to child LLMs.

L

Leo: That sounds almost like an agent already.

M

Maya: It's the first step into multi-agent systems. The parent calls child agents the way it would call tools.

L

Leo: Is there one more?

M

Maya: Evaluator and optimizer: one role creates and another scores. Retry within an attempt limit, then report failure if the result still does not pass.

L

Leo: So grading could use that one, to check its own grades.

M

Maya: Choose which decisions remain fixed in code. An orchestrator can still generate a variable plan, so its workers and limits need controls.

04What autonomy costs

L

Leo: Then why is the tutor an agent at all? Why not a big workflow?

M

Maya: A learner's question can go anywhere. The tutor may need their weak points, a card, or nothing at all.

L

Leo: So the steps can't be written in advance.

M

Maya: That's when autonomy pays. It buys flexibility.

L

Leo: And what does it cost?

M

Maya: Predictability, latency and money. Each turn can add a model call; limits bound the run without guaranteeing a successful answer.

L

Leo: While grading always takes one call.

M

Maya: Right. So grading stays in fixed steps, and the tutor is an agent.

L

Leo: And if the tutor's answers start to vary too much?

M

Maya: Then you look for the part that could be fixed in code, and move it out of the loop. An agent can call a workflow as one of its tools.

05Leo explains it back

M

Maya: Suppose a new teammate calls grading "our agent." How do you correct them?

L

Leo: There are three levels: call it once, arrange it as a workflow, or let it decide as an agent.

L

Leo: An agent is a loop. The LLM picks the next move, and the harness runs the tool and hands back the result.

M

Maya: And who calls the API?

L

Leo: Never the model. It only asks, and the harness calls it.

L

Leo: Choose the least autonomy that works. Grading runs in fixed steps, and only the tutor needs to be an agent.

M

Maya: Add the patterns to that list. Chaining, routing and the rest are what you try before the ladder's last rung.

Summary in three lines

  1. LLM features sit on three levels: one call, a workflow, or an agent that decides its steps.
  2. An agent is a loop: the LLM picks the next move, and the harness runs the tool.
  3. Try workflow patterns first; choose the least autonomy that works.
