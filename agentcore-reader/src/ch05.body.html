Where does an agent actually run?

After this page you can explain what AgentCore Runtime takes over, and why each session gets its own private room. You can also describe the one rule an agent must follow, and how versions and endpoints keep production stable.

About 8 min readThe whiteboard room

In this page

  • Why not run the agent on Lambda?
  • What is a private room per session?
  • What must an agent offer, and how long can it run?
  • How are versions deployed and rolled back?

The whiteboard room. Leo has drawn the API's Lambda functions, and the tutor is in a separate box.

01Why not Lambda

L

Leo: The whole API runs on Lambda. Why is the tutor over here, on Runtime? Isn't an agent just another function?

M

Maya: What does the tutor do during one conversation?

L

Leo: It calls a tool, waits for the result, calls the next tool. Again and again.

M

Maya: And what is Lambda built for?

L

Leo: Short tasks that finish quickly. Each call has a time limit.

M

Maya: So a long conversation can run past that limit. That's the first problem.

L

Leo: Then why not a container, on ECS? No time limit there.

M

Maya: True. But now you design your own isolation and scaling. Keeping each user's conversation separate, and removing servers when nobody needs them.

L

Leo: So Lambda has a time limit, and on ECS we build everything ourselves.

M

Maya: That's the gap. Runtime takes over three jobs: keeping the agent running, keeping sessions isolated, and scaling up or down.

L

Leo: And we only write the agent's own code.

M

Maya: Right. The tutor runs on Runtime, and the rest of the API stays on Lambda. Each fits its job.

02A private room per session

L

Leo: What does "isolated" mean in practice?

M

Maya: When Runtime receives a request, it sets up a microVM, a small virtual machine, just for that session. The agent runs inside it.

L

Leo: One per user?

M

Maya: One per session. Each user's session gets its own microVM, so conversations never mix.

L

Leo: And when the session ends?

M

Maya: Its microVM is thrown away, like cleaning up a room after the work is done.

L

Leo: Then how does a learner come back to the same conversation?

M

Maya: They send a request with the same session ID, and Runtime shows them back to the same room.

L

Leo: So Runtime remembers the conversation.

M

Maya: No, that's Memory's job. Runtime's job is only to set up an isolated place to run the agent.

L

Leo: So Runtime gives the room, and Memory brings back the notebook.

M

Maya: Yes. Keep them apart in your head, because they fail in different ways.

L

Leo: What happens without that, in a prototype?

M

Maya: Three problems people overlook. A shared server handles sessions carelessly, and one user's conversation leaks into another's.

L

Leo: That's the worst one.

M

Maya: Then long tasks get stuck when they hit a timeout. And in production, the agent often needs a system that only exists inside the company network.

L

Leo: Can Runtime reach that?

M

Maya: It can connect to a database or an internal system inside a VPC, a private network. Session isolation, long runs and VPC connections answer exactly these three.

03Long runs and one rule

L

Leo: How long can a session run?

M

Maya: As of May 2026, Runtime supports runs of up to 8 hours. You can hand off long tasks, like research or data analysis, and let them keep going.

L

Leo: But a learner won't wait in silence for eight hours.

M

Maya: So Runtime supports both asynchronous processing and streaming. Streaming sends small pieces of the answer as soon as they're ready.

L

Leo: Long tasks in the background, short answers streamed to the screen.

M

Maya: Right. A chat like the tutor suits streaming, because the learner is watching the text appear.

L

Leo: And a research task suits the background.

M

Maya: You start it, go to lunch, and read the result later.

L

Leo: Does Runtime care that we use Strands?

M

Maya: Not at all, or which LLM we call. There's one rule: the agent must offer two HTTP endpoints.

L

Leo: Which two?

M

Maya: /invocations for calls, and /ping to check that it's alive. Follow that, and Strands, LangGraph or CrewAI agents are hosted the same way.

L

Leo: That's a small contract.

M

Maya: And it isn't HTTP only. On the same Runtime, an agent can be an MCP server that offers tools.

L

Leo: Or an A2A server?

M

Maya: Yes, one that talks to other agents.

L

Leo: What about voice?

M

Maya: Support for two-way streaming, for voice conversations, is growing. That area changes fast, so check the developer guide.

04Versions and cost

L

Leo: How does the code get onto Runtime?

M

Maya: Two main ways. Build a container image and place it in ECR, or pass your code directly.

L

Leo: Lots of settings, I suppose.

M

Maya: Many small ones. But the AgentCore CLI handles everything from building to deploying, so you don't redo the steps each time.

L

Leo: And every deploy replaces the old one?

M

Maya: Every deploy adds a new version. Requests are received by an endpoint, and the endpoint decides which version gets the traffic.

L

Leo: So production can stay on a version we tested.

M

Maya: While a staging endpoint tries the newest. And if something goes wrong, you point the production endpoint back to an older version.

L

Leo: Rollback without a new build.

M

Maya: That's the point of keeping versions. The old code is still there, tested, and one change away.

L

Leo: Like a Lambda alias pointing at a version?

M

Maya: The same idea, yes. On Runtime it's built into how every deploy works.

M

Maya: Now, who calls Runtime? It accepts AWS IAM with SigV4 signing, or JWT with OAuth. Which one depends on who's calling.

L

Leo: And the cost?

M

Maya: You pay only for what you use. The design idea is that cost goes down when the agent isn't really working, like while it waits for the LLM.

L

Leo: What are the numbers?

M

Maya: They change often, so I'll leave them out. What matters is the trade.

L

Leo: Which trade?

M

Maya: Isolation and long sessions, against paying for session time and running a second deploy path beside Lambda's.

L

Leo: Two ways to ship code instead of one.

M

Maya: And two sets of limits to learn, and two places to look when something breaks.

L

Leo: So the second path has to be worth what it costs.

M

Maya: Yes. For the tutor, it's worth it. For a request that ends in a second, Lambda is still the better home.

05Leo explains it back

M

Maya: Put my answer to your first question into your own words. Why isn't the tutor on Lambda?

L

Leo: Runtime gives one isolated microVM per session, and throws it away when the session ends.

L

Leo: It supports long runs, up to 8 hours, with streaming or background work.

L

Leo: Any framework works, as long as the agent offers /invocations and /ping.

M

Maya: How do we ship a change safely?

L

Leo: Each deploy is a version, and endpoints choose which version gets traffic.

M

Maya: Remember what Runtime doesn't do, too. It hosts the session; remembering the conversation belongs to Memory.

Summary in three lines

  1. Runtime takes over keeping agents running, isolating sessions, and scaling.
  2. Each session gets its own microVM; the only rule is to offer /invocations and /ping.
  3. Versions and endpoints let you test new code and roll back while production stays stable.
