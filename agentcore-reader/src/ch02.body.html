What changes when an agent goes to work at a company?

Leo’s laptop agent shares one history and one API key. Company use needs separate conversations, authorized access and evidence when an answer goes wrong.

Coffee in the kitchen. Leo spent the weekend building an agent of his own.

01MCP and A2A

L

Leo: I built an agent this weekend. It uses three MCP tools, and it works fine on my laptop. So why do companies need a whole platform?

M

Maya: Let's start with the tools. What does MCP give you?

L

Leo: A way to plug tools in. I found servers for search and for my notes.

M

Maya: Right. MCP, the Model Context Protocol, is a standard for describing tools and calling them in one common way.

L

Leo: So different agents can share its interface?

M

Maya: Yes, when their MCP capabilities are compatible. Each server still needs authentication and permissions for the caller.

L

Leo: And then?

M

Maya: Compatible MCP clients can use that interface, including Strands and Claude Code. Support and authorization still need checking.

L

Leo: Like every plug fitting the same USB port.

M

Maya: It reduces connection differences rather than making every tool interchangeable. Gateway exposes supported targets through MCP.

L

Leo: And A2A? I've seen it next to MCP everywhere.

M

Maya: A2A, Agent2Agent, connects something different. It lets one agent ask another agent to do a job.

L

Leo: Without knowing how the other one is built?

M

Maya: Right. You use its A2A interface, rather than its internal framework. Responses can show completion, failure, rejection or a need for more input.

L

Leo: So the other agent is a closed box to us.

M

Maya: Yes. MCP connects an agent to tools and data. A2A connects agents to agents.

L

Leo: So they compete? I'd pick one?

M

Maya: No, they sit side by side. An agent can use tools through MCP and still hand a whole job to another agent through A2A.

02Bedrock Agents and AgentCore

L

Leo: I've also seen tutorials for Bedrock Agents. Is that the same thing as AgentCore?

M

Maya: It's the older service. You wrote instructions in the console and registered tools as an "Action Group."

L

Leo: And AWS ran the loop?

M

Maya: A loop AWS built for you, like ready-made furniture. Easy to use, but hard to change on the inside.

L

Leo: Hard to change how?

M

Maya: If the built-in loop didn't fit your task, you had few ways to change what happened inside it.

L

Leo: Could you bring your own framework?

M

Maya: No. An agent built with something like LangGraph couldn't come in. And it used Bedrock models only.

L

Leo: So AgentCore replaced it?

M

Maya: Here we use AgentCore components around code-defined agents. That lets the team choose its framework while following the hosting and tool contracts.

L

Leo: Then where does the agent come from?

M

Maya: You write it in code. AWS recommends Strands Agents, an open-source SDK, but Strands, LangGraph and CrewAI all work.

L

Leo: And models outside Bedrock?

M

Maya: Those can work through the chosen framework and provider. The team controls its loop within the service’s contracts and limits.

L

Leo: Should I still learn Bedrock Agents?

M

Maya: AWS closed Bedrock Agents Classic to new customers on 30 July 2026. Existing customers can continue; current account eligibility needs checking.

L

Leo: Which is why my roadmap only covers AgentCore and Strands.

M

Maya: That's the reason.

03The wall

L

Leo: Back to my weekend agent. The loop is a few dozen lines. What's actually hard?

M

Maya: Making it work for thousands of people at a company. Who uses yours?

L

Leo: Just me.

M

Maya: At a company, thousands of people use it, and each is allowed to see different information.

L

Leo: So identity matters.

M

Maya: And it has to run for many people at once, without mixing up their conversations.

L

Leo: Mine keeps one history in memory. Two users would read each other's chat.

M

Maya: That's the first thing a company would have to fix.

L

Leo: My agent has one API key for everything.

M

Maya: At a company, permissions are checked for every action: who it's for, and what is allowed.

L

Leo: And quality? Mine is fine if it seems to work.

M

Maya: At a company, it's measured with scores and checked after every change. And when it fails, you can't just try again.

L

Leo: You'd have to explain what happened.

M

Maya: Trace the cause from records, and explain it.

L

Leo: My agent keeps no records at all. When it gave a strange answer, I just ran it again.

M

Maya: At a company, "run it again" isn't an answer. Someone will ask which tool it called, with what, and why. Here's the whole wall in one picture.

L

Leo: What could stop my prototype from reaching company use?

M

Maya: Your shared history and unrestricted key already reveal two gaps. Authentication, resource permissions, evaluation, records and spending controls need explicit designs.

L

Leo: The things any new hire gets on day one.

M

Maya: Right: a badge, a desk, rules to follow. AgentCore provides those as ready-made parts.

L

Leo: So the weekend agent isn't wasted. It's the brain, without the badge and the desk.

M

Maya: Yes. The loop you wrote still runs; it just runs inside those parts.

04What a platform costs

L

Leo: Does our tutor use those parts?

M

Maya: Only the company-side ones. Sign-in, and limits on which learner's data it can reach. Our cost limits sit beside it.

L

Leo: Couldn't we build those ourselves?

M

Maya: We could build them. Managed components may save operating work, but the team still configures permissions and tests the boundaries. The tutor’s teaching behavior remains our own work.

L

Leo: And the tutor itself is what makes us different.

M

Maya: So that's where our time should go: the prompts, the tools and the tests of the tutor.

L

Leo: So the platform takes over some operating work?

M

Maya: Yes. We still configure and test the boundaries. The tradeoff includes an AWS dependency, component usage charges and retained resources.

L

Leo: So if AgentCore changes, we change with it.

M

Maya: For this design, compare saved operating work with service limits and cost. A small team still needs evidence for that choice.

05Leo explains it back

M

Maya: Your weekend agent is going to work here. What does it need first?

L

Leo: MCP connects it to tools, and A2A lets it ask other agents for work.

L

Leo: The loop is the easy part. A company adds identity, rules for every action, memory kept apart per user, and monitoring.

M

Maya: And why a platform, rather than our own code?

L

Leo: Because managed components can reduce repeated operating work. We still own their configuration, and Classic remains available to existing customers.

M

Maya: Mind the price of that choice as well: a dependency and a cost per use, in exchange for work we don't repeat.

Summary in three lines

  1. MCP connects an agent to tools and data; A2A lets agents ask each other for work.
  2. AgentCore can host code-defined agents that meet its contracts; Classic remains a separate managed service.
  3. The hard part is the company side: identity, rules, memory and monitoring.
