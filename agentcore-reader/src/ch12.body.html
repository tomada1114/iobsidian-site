How do you design an agent you can defend?

After this page you can explain how document search can leak what a user shouldn't see. You can say what an agent needs before it touches money. And you can use the Generative AI Lens as a checklist, and defend choosing no agent.

About 8 min readAfter the design review

In this page

  • How can document search leak?
  • What must be true before an agent pays?
  • What does the Generative AI Lens ask?
  • When is "no agent" the right answer?

After Tuesday's design review. Next week Leo presents the tutor's design, and he's rehearsing.

01Permissions in search

L

Leo: I've spent a week on the tutor's prompt. If the prompt is good, the design is good, isn't it?

M

Maya: The prompt is one part. Someone will ask about search first. What does the tutor read?

L

Leo: Documents and cards, through search. Like Bedrock Knowledge Bases, which lets an agent search internal documents.

M

Maya: Useful. But there's an easy trap. The permission on the original document isn't always carried over to the search result.

L

Leo: What does that look like?

M

Maya: Say an HR evaluation folder is meant only for a few managers. Inside the search index, that difference may not be kept.

L

Leo: So anyone who asks could get an answer from that folder.

M

Maya: By mistake, yes. And nobody would notice, because the answer would sound perfectly normal.

L

Leo: So a good prompt can't help here.

M

Maya: No. The prompt never sees which documents were filtered. The fix is metadata, extra data about the data, on each document, saying who may read it.

L

Leo: And the search filters on it.

M

Maya: Using the metadata and the permissions of the current user. The agent acts on behalf of the user.

L

Leo: The asker's permissions, not the agent's.

M

Maya: Right. Then documents the user can't see never get mixed into the answer.

L

Leo: And the tutor?

M

Maya: It reads only the signed-in learner's data. That's the same idea at our size.

02When an agent pays

L

Leo: Someone asked whether the tutor could buy a course upgrade for a learner. Is that just another tool?

M

Maya: Payments deserve extra care. There's a Deep Dive module on it, "Agents that transact."

L

Leo: What should I remember?

M

Maya: Three points. First, set a limit on the budget. Second, a person approves any payment above a certain amount.

L

Leo: And third?

M

Maya: Keep a record of what was paid, and how much.

L

Leo: And without all three?

M

Maya: Then it's safer to say it's too early to let an agent pay.

L

Leo: So for the upgrade question, the answer is "not yet."

M

Maya: Or "not until those three exist." That's an answer a reviewer can accept.

L

Leo: Why the record, if a person already approved it?

M

Maya: Because later someone will ask what the agent paid, and why. An approval without a record can't answer that.

03A checklist and real code

L

Leo: How do I know I haven't missed a whole area?

M

Maya: The AWS Well-Architected Framework has a Generative AI Lens, made for these workloads. It asks questions under six pillars.

L

Leo: Which ones?

M

Maya: Operational excellence, security, reliability, performance efficiency, cost optimization and sustainability.

L

Leo: What does operational excellence ask about an agent?

M

Maya: How you check a change before deploying it, and how you notice when behavior changes.

L

Leo: And security?

M

Maya: Whether permissions are kept to the minimum, and whether you're ready for indirect prompt injection.

L

Leo: Reliability must be about failures.

M

Maya: Is there a fallback, a backup plan, if a model or tool fails? Can a long task resume from where it stopped?

L

Leo: And performance efficiency?

M

Maya: How you keep delay low, with caching, streaming and model choice.

L

Leo: Cost optimization I can guess. Split cost by department, and use different models for different tasks.

M

Maya: Right. And sustainability asks whether you can cut models bigger than needed, and wasted calls.

L

Leo: So I can walk the tutor through all six before the review.

M

Maya: That's how to use it: as a checklist, to find your weak part. There's a Skill Builder course on the lens.

L

Leo: A fallback, for example. I don't have one.

M

Maya: Then that's the question you'll get. Better to find it yourself this week.

L

Leo: What would a fallback even be for a tutor?

M

Maya: A smaller model when the main one fails, or a plain "try again" message instead of an error page.

L

Leo: Is there real code I can compare against?

M

Maya: GenU, generative-ai-use-cases. It's an open-source generative AI app for companies, published by AWS Japan.

L

Leo: All of it?

M

Maya: No. Look at four parts: SAML sign-in, the security settings, where AgentCore Runtime is used, and the chat feature that uses MCP.

L

Leo: And compare them with what we've talked about.

M

Maya: You'll see how the parts connect far more clearly than from any diagram.

L

Leo: Should I copy its settings?

M

Maya: Read them to understand the choices. Then make your own, for our learners and our risks.

04Choosing no agent

L

Leo: And the question I'm dreading: "Why an agent at all?"

M

Maya: Governance, cost, security and permissions all get heavier as you give an agent more responsibility.

L

Leo: So a smaller scope means fewer things to check.

M

Maya: Right. For work with fixed steps, a workflow is still the cheapest choice.

L

Leo: Card grading, for example.

M

Maya: It stays a workflow. The tutor is an agent because a learner's question can go anywhere.

L

Leo: So "plain code" is an answer too.

M

Maya: For fixed, risky work, often the best one. No LLM means nothing to trick.

L

Leo: And the narrow agent, bottom right?

M

Maya: Open-ended but risky. Keep its tools few, its rights narrow, and put a person's approval before anything it can't undo.

L

Leo: So that corner needs every guard at once.

M

Maya: Which makes it the most expensive corner to live in. Stay there only when the task truly needs it.

L

Leo: What do the company-wide reviews usually ask?

M

Maya: Who manages which agent? Is there a cost limit?

L

Leo: And injection?

M

Maya: Are you protected against indirect prompt injection? And are document permissions still enforced?

L

Leo: If I can answer those, "why an agent?" is easy.

M

Maya: Because you'll have shown you only used one where you had to.

05Leo explains it back

M

Maya: Give me your opening for next week, in a few lines.

L

Leo: Search filters by the asker's permissions, and the tutor reads only the signed-in learner's data.

L

Leo: No agent touches money without a budget limit, human approval and a record.

L

Leo: We checked the design against the six pillars of the Generative AI Lens.

M

Maya: And "why an agent?"

L

Leo: Only the tutor is one, because its questions are open-ended. Grading stays a workflow.

M

Maya: Say your weak pillar out loud before anyone asks. A known gap with a plan is easier to defend than a surprise.

Summary in three lines

  1. Search must filter by the asker's permissions, or documents leak into answers.
  2. Before an agent pays, it needs a budget limit, human approval and a record.
  3. Use the Generative AI Lens as a checklist, and choose no agent when steps are fixed.
