Does every AI feature need to be an agent?

Grading has a known input and verdict, while a tutor may need different lookups for each question. Those tasks need different amounts of model control.

01Three words, plainly

Quickturn needs to grade a typed answer against a rubric. That task may require one model call: input goes in and a verdict comes back. A workflow coordinates several steps whose order is determined by code. An agent gives the model some choice about the next step or tool.

The surrounding harness executes requested tools, returns their results and enforces limits. A tutor may choose whether to inspect recent mistakes before answering. A grader with a known input and output does not need that open-ended loop.

02The ladder

Start with the simplest adequate interaction: one call, a chain, a router or a controlled workflow. Parallel calls and a second model checking output can still be workflows when code owns the plan.

Quickturn uses one call for grading, a generation-and-review workflow for cards, and an agent for the tutor's variable multi-turn lookups. Its core timed drill remains a deterministic application flow.

03What an agent costs

An agent can take different paths for the same request, increasing variable latency, cost and testing difficulty. Each tool adds an action that untrusted input might influence. Define turn, time and spending limits even when the model is allowed to choose steps.

A fixed workflow is easier to compare against expected results. A router can handle variation without giving every request a general agent. A helpdesk, for example, may route ordinary password resets to a known workflow and reserve open-ended investigation for unusual cases.

04A helpdesk that split its traffic

The helpdesk example also needs evaluation of the router. Past tickets can be labeled with the route a person chose; uncertain cases can escalate. Measure latency, cost and task success by route rather than assume the agent is always the more capable option.

A multi-turn conversation does not itself require an agent. Guided sign-up can span several turns while code determines each step. Introduce model-directed tool use when the possible next actions genuinely depend on information that cannot be planned beforehand.

Summary in three lines

  1. A call answers once, a workflow runs steps our code chooses, and an agent lets the model choose the steps.
  2. Give the model the decisions the task requires, and keep planned steps and limits in code.
  3. Consider an agent when variable tool choices are useful, and evaluate its cost and success against simpler routes.
