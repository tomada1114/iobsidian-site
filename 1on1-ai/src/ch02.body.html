What am I actually paying for in one LLM call?

A compact grade may use fewer output tokens than input tokens and still spend a substantial share on output. Context, rates and latency need separate measurements.

01Tokens and the context window

Tokens are model-specific pieces of text, not a fixed number of words or characters. A call's context includes the instructions, examples, input and any conversation history supplied by the application. Conversational memory is provided by that surrounding system.

The context and output limits constrain the request. Set an output cap high enough for a complete verdict and low enough to bound cost and latency. Monitor truncation rather than infer that the longest previously observed answer is an absolute upper bound.

02Why answers change, and what takes time

Models generate tokens using learned probabilities and sampling controls. Lower temperature can reduce variation but does not guarantee identical results. Quickturn stores the first accepted grade instead of requiring a repeated call to reproduce it.

Latency includes request and queue overhead, processing the input and generating output. Longer responses often take longer, which is one reason the grader returns a compact verdict rather than a full essay. Measure the actual endpoint instead of predicting latency solely from token count.

03Price per call, and caching

A token-priced call depends on input and output volume, with distinct rates. A comparison needs the same model, endpoint, Region and date. Two small calls may cost less than one larger call.

The cost illustration uses 1,500 input and 200 output tokens at explicitly assumed rates. It is not a quote for every Tokyo inference profile. Prompt caching can discount a stable prefix, while cache writes and expiry have their own rules.

Quickturn keeps instructions and examples before the changing answer and records ordinary input, output, cache-read and cache-write usage separately. It measures per-answer versus per-round grading, including latency and failure behavior, before choosing. Extra examples earn their cost only if evaluation shows a useful improvement.

04A bill that grew every week

An agent's bill can grow without traffic growth if each turn resends a longer history and more tool definitions. Request counts alone conceal that change. Track tokens and cost per conversation, trim irrelevant history, use supported caching and bound the output.

Quickturn records model, prompt and rubric versions with latency and usage. That connects a cost increase to the particular task and configuration that produced it.

Summary in three lines

  1. A call uses the context supplied by the application; conversation memory and caching require surrounding system support.
  2. Input and output contribute differently to cost and latency; the same input can produce a different answer.
  3. Put the stable part first so it can be cached, and record all four token counts on every call.
