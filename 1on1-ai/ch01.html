Does every AI feature need to be an agent?

After this page you can tell a single LLM call, a workflow and an agent apart. You can also say what each step toward an agent costs, and when an agent is worth it.

About 8 min readAt the whiteboard

In this page

  • What are a call, a workflow and an agent?
  • How do the shapes build on each other?
  • What does an agent cost, and when does it pay?
  • How did a helpdesk team pick its shape?

The whiteboard room, right after a planning meeting.

01Three words, plainly

L

Leo: In the meeting, the PM asked to make grading of typed answers "an AI agent". Which agent framework should I look at?

M

Maya: Before a framework, let's check what "agent" means. What would the agent do for grading?

L

Leo: Read the learner's answer, compare it with the expected one, and give a verdict. With some reasoning.

M

Maya: That's one question and one answer. Let's define three words, because people use them loosely.

L

Leo: Okay.

M

Maya: An LLM call is one request and one answer. You send a prompt, the model sends text back.

L

Leo: And a workflow?

M

Maya: Code that decides the order of several calls. Call one, check the result, call two. Our code picks every step.

L

Leo: Then an agent is a smarter workflow?

M

Maya: An agent is a loop where the model decides the next step. It chooses which tool to call, and it stops when it decides to.

L

Leo: Wait. The model runs tools?

M

Maya: Never by itself. It asks for a tool, and the program around it, called the harness, runs the tool and sends back the result.

L

Leo: So in a workflow, our code decides when it's done. In an agent, the model does.

M

Maya: That's the difference that matters. Everything else follows from it.

L

Leo: What does that look like for the tutor?

M

Maya: A learner asks why they keep missing a phrase. The model asks for their recent mistakes, then for the card, then answers.

L

Leo: And nobody wrote those three steps down.

M

Maya: Right. With another question, it might ask for something else, or for nothing at all.

02The ladder

L

Leo: I thought workflows were the older, weaker version. Agents are what everyone builds now.

M

Maya: Anthropic's article "Building effective agents" says nearly the opposite: start with the simplest thing that works. Let me draw the shapes as a ladder.

L

Leo: What's a chain?

M

Maya: Several calls in a fixed order, each using the last one's output. A router is one call that picks which path the request takes.

L

Leo: And a fixed workflow?

M

Maya: Our code runs the steps, maybe in parallel, maybe with one model checking another's work. The model fills in parts, but the plan is ours.

L

Leo: Let me place our features. Grading is one call that returns a typed verdict.

M

Maya: Right, the first rung. Our code does everything around that call, behind a task port.

L

Leo: Card generation writes a card, checks it, and has it reviewed. That's a chain.

M

Maya: Yes. An AI writer drafts, an AI reviewer judges, and a person supervises the stamp.

L

Leo: And the tutor?

M

Maya: The tutor talks with a learner, over many turns, and chooses what to look up in their history. That one is an agent.

L

Leo: So one agent in the whole product.

M

Maya: And not at the center. Our core loop is a timed drill, not a conversation.

03What an agent costs

L

Leo: But why not use an agent anyway? More freedom should mean better answers.

M

Maya: Freedom has a price. More calls per request. No fixed length, so no fixed cost or latency.

L

Leo: And?

M

Maya: Different paths on the same input. That makes it harder to test and to evaluate. And every tool it can call is something an attacker can try to steer.

L

Leo: So when does it pay?

M

Maya: When the steps can't be written down in advance. Here's my test: can you draw the steps on the whiteboard before the request arrives?

L

Leo: For grading, yes. Read, compare, return a verdict.

M

Maya: Then it's a workflow. And it has something an agent rarely has: an expected answer.

L

Leo: You mean we know what the verdict should be?

M

Maya: For about two thousand reviewed alternative answers, yes. So we can test a prompt change against them. With an agent, two good runs may take different paths, and there's no single right one to check.

L

Leo: So choosing the smaller shape is also what makes testing possible.

M

Maya: Then let me put our features on two questions.

L

Leo: But workflows break on inputs nobody planned for. A learner types something strange, and the fixed steps don't fit.

M

Maya: That's true. And that's exactly where a router belongs. Or an agent, only for those rare, unusual cases.

L

Leo: So the strange cases get the expensive shape, and the normal ones don't. And a scripted chat, top left?

M

Maya: A conversation with fixed steps, like a guided sign-up. Several turns, but our code still decides each one.

L

Leo: So the strange cases pay, and the rest stay cheap.

M

Maya: Right. That's how you keep most traffic cheap and testable.

04A helpdesk that split its traffic

L

Leo: Have you seen that work?

M

Maya: At my last company, we built an IT helpdesk agent. Every ticket went through the agent loop.

L

Leo: What went wrong?

M

Maya: Nothing dramatic. It was just slow and costly, and we couldn't say whether a change made it better.

L

Leo: Why not?

M

Maya: Every ticket took a different path, so there was no expected answer to compare against. Then we looked at the tickets.

L

Leo: And?

M

Maya: Most were password resets and access requests. They followed three fixed paths.

L

Leo: So you put a router in front.

M

Maya: Yes. The router sent those to three fixed workflows, and only unusual tickets reached the agent.

L

Leo: Couldn't the router send a ticket to the wrong path?

M

Maya: It could, so the router had its own tests: past tickets with the path a person chose. And any ticket it wasn't sure about went to the agent.

L

Leo: What changed?

M

Maya: Cost per ticket fell. And we could finally evaluate, because most traffic had one expected path.

L

Leo: So I tell the PM grading stays a workflow.

M

Maya: Tell them why: we can draw its steps today. If a feature ever needs open-ended, multi-turn tool use, we'll consider an agent for it.

05Leo explains it back

M

Maya: The PM asks again tomorrow. What do you say?

L

Leo: Start from the smallest shape: one call, then a chain or a router. Move up only when you can't write the steps down in advance.

L

Leo: Every step up costs calls, money and predictability. Different paths on the same input are hard to test.

L

Leo: So an agent is for open-ended, multi-turn tool use, like the tutor. Grading is one call with a typed answer.

M

Maya: And for strange inputs?

L

Leo: A router in front, and the expensive shape only for the rare, unusual cases.

M

Maya: The model never runs a tool itself. Whatever an agent does, our harness does it, so our code still sets the limits.

Summary in three lines

  1. A call answers once, a workflow runs steps our code chooses, and an agent lets the model choose the steps.
  2. Climb the ladder only as far as you must: each step hands the model one more decision.
  3. Use an agent when the steps can't be drawn in advance, and route ordinary traffic around it.
