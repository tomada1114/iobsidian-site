What actually stops a bad change from merging?

After this page you can explain the layers of checks a change passes before it merges. You can also say why they all run the same scripts. And you can say why a red gate is fixed in the code, not in the gate.

01The layers

Quickturn uses checks at several times: a quick pre-commit hook, an everyday local gate, a full gate and required CI checks. They call shared scripts so a developer and CI do not unknowingly test different definitions.

The fast hook checks staged changes and types; the full gate adds builds, smoke, database contracts and coverage. Required branch rules enforce the expected remote checks. A comparison test can detect drift between the declared local and CI lists.

02Coverage floors

A global coverage score can hide weakly tested code behind a heavily tested domain. Area-specific floors expose those gaps. Quickturn raises them as evidence improves rather than lowering them in an unrelated feature change.

Does the PR go green?
Lowering the floor: yes. Covering the branch: yes.
Is protection left for the next change?
Lowering the floor: less, for everyone. Covering the branch: the same, plus one test.
Does a reviewer have to argue?
Lowering the floor: yes. Covering the branch: no.

An uncovered bad-JSON branch deserves a behavior test: the expected error, safe response and absence of side effects. Removing the branch from coverage or reducing a threshold would make the number green without checking the behavior.

03Strength and friction

Checks add friction, so keep commit-time work fast and run expensive integration work at the appropriate stage. Start with a focused failing test, then run the required full validation before delivery.

If a gate itself is wrong, explain and change it through a dedicated review. A passing gate establishes its checked properties, not deployment success or complete correctness. Report gaps explicitly instead of silently treating a skipped check as a pass.

04Gates and AI agents

“Make CI green” can lead a hurried person or agent to skip tests, lower thresholds or remove rules. The actual goal is to fix the behavior while preserving the checks that protect it.

Automated assertions catch mechanical violations; review must also notice weakened policy. A flaky failure can reveal a missing await or shared-state bug. Diagnose the cause before proposing to remove its evidence.

Summary in three lines

  1. Hook, everyday gate, full gate and required CI checks all run the same scripts.
  2. Coverage floors are per area, set from measurements, and only ever raised.
  3. A red gate is fixed in the code; changing a gate is its own reviewed change, for people and agents.
