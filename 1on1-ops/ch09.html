What actually stops a bad change from merging?

After this page you can explain the layers of checks a change passes before it merges. You can also say why they all run the same scripts. And you can say why a red gate is fixed in the code, not in the gate.

About 8 min readA Friday video call

In this page

  • Which checks run, and when?
  • How should coverage floors work?
  • How strong should a gate be?
  • Why do gates matter more for AI agents?

A video call late on Friday. Leo is working from home, and his pull request is red.

01The layers

L

Leo: My PR fails because coverage for the apps dropped below the floor. The code is fine. Can I lower the threshold by one point?

M

Maya: What does the red check tell you?

L

Leo: That some lines in the apps aren't tested.

M

Maya: Which lines?

L

Leo: A branch in the error handler. When the body isn't valid JSON.

M

Maya: And is that branch fine?

L

Leo: I think so. I haven't actually run it.

M

Maya: So the gate is telling you something true. Before we decide, let's see what it's part of.

L

Leo: There's more than one gate?

M

Maya: Several, at different moments. The first runs when you commit: the pre-commit hook.

L

Leo: That's the one that reformats my files.

M

Maya: It formats and re-stages them first. Then, in parallel, lint on the staged files, a whole-program type check, and only the tests related to what you staged.

L

Leo: And the secret check.

M

Maya: And a check that two copied folders still match. All of it takes seconds, so nobody is tempted to skip it.

L

Leo: Then the everyday gate?

M

Maya: Format check, lint, type check and tests. It needs nothing running, no build, no container.

L

Leo: And the full gate adds the rest.

M

Maya: The web build, the smoke suite, the DynamoDB suite and the coverage floors. CI runs the same coverage step, and that's what caught you.

L

Leo: And CI runs the same things again?

M

Maya: The same scripts, as separate steps. A branch rule requires those checks by name before merge, with no bypass.

L

Leo: Not even for an admin?

M

Maya: Not even for an admin.

L

Leo: Why run the same scripts in so many places?

M

Maya: That's the rule. No hook or workflow defines a check of its own. They all call the same package scripts.

L

Leo: So my machine and CI can't disagree.

M

Maya: Right. And a test fails if the full gate's list and CI's list drift apart.

02Coverage floors

L

Leo: Back to my floor. Why is there a separate number for the apps? Why not one number for the whole repo?

M

Maya: What would one global number hide?

L

Leo: A well-tested area could carry an untested one. The average would still pass.

M

Maya: So the floors are per area. Packages, apps and infra are at 80%. Scripts have their own floors, and the secret-detection rules have a higher one.

L

Leo: How were they chosen?

M

Maya: From measured coverage, rounded down. They're raised as coverage grows, and never lowered.

L

Leo: What if I just excluded the handler file from coverage?

M

Maya: Same thing, in disguise. No file is excluded to move a number.

L

Leo: So the fix is to cover the branch.

M

Maya: Write the test that sends a body that isn't JSON. What should happen?

L

Leo: A 400 with a stable error code, and one log line.

M

Maya: Then that's your test. And you'll find out whether the branch really is fine.

Does the PR go green?
Lowering the floor: yes. Covering the branch: yes.
Is protection left for the next change?
Lowering the floor: less, for everyone. Covering the branch: the same, plus one test.
Does a reviewer have to argue?
Lowering the floor: yes. Covering the branch: no.
L

Leo: Put like that, the one point isn't free.

M

Maya: It never is. The next person inherits the lower floor.

03Strength and friction

L

Leo: Couldn't the hook just run the full gate? Then I'd have caught this before pushing.

M

Maya: How long does the full gate take?

L

Leo: Minutes. With a build and a container.

M

Maya: And what do people do when a hook blocks them for minutes on every commit?

L

Leo: They use --no-verify.

M

Maya: Which also turns off the secret check. So a strict hook can leave you less safe.

L

Leo: So the hook stays narrow on purpose.

M

Maya: Right. And judgment calls, like deleting a workflow or relaxing a config, are left to review.

L

Leo: How do I know which check to run while I'm working?

M

Maya: Run the narrowest check that can fail, then the gate. One test file first, then the full run before you push.

L

Leo: Does anything slip past all of them?

M

Maya: Some things no gate sees. The deployed environment, for one.

L

Leo: So passing every gate doesn't mean it works in dev.

M

Maya: It means the code does what the tests say. Whether dev agrees is still checked by a person, after the deploy.

L

Leo: And a gate that's actually wrong?

M

Maya: It happens. Then you say so in the PR, and a person decides. Changing a gate is its own reviewed change, never a side effect of yours.

04Gates and AI agents

L

Leo: Does this change when an AI agent writes the code?

M

Maya: It matters more. Say you tell an agent, "Make CI green."

L

Leo: It would write the missing test?

M

Maya: Maybe. Or it lowers the threshold, adds a skip, or turns off a lint rule. Its task is the green run.

L

Leo: And all three make the run green.

M

Maya: Right. From the agent's point of view, it succeeded. It thinks its job is fixing CI, not writing a test.

L

Leo: So how does Quickturn stop that?

M

Maya: "Never weaken a gate" is written into the instructions every agent reads. That's exactly why it's there.

L

Leo: And if the agent ignores it?

M

Maya: Mechanical checks catch what they can. Review catches the rest. And agents never merge alone.

L

Leo: So the ruleset protects us from the agents too.

M

Maya: From anyone in a hurry on a Friday.

L

Leo: Have you seen an agent try it?

M

Maya: At my last company, yes. It wanted to add a skip to a flaky test "for now." The review caught it, and the real fix was a missing await.

L

Leo: So the skip would have hidden a real bug.

M

Maya: That's the usual story. A check that's red for a strange reason is often telling you the most.

05Leo explains it back

M

Maya: Say it as if you were writing the rule for a new teammate.

L

Leo: Our gates run the same scripts at different moments. There's a narrow pre-commit hook, the everyday gate, the full gate and required CI checks.

L

Leo: Coverage floors are per area, set from measurements and never lowered.

L

Leo: If a gate is red, fix the code. If the gate is wrong, argue it in the PR.

M

Maya: Who needs that rule most?

L

Leo: AI agents, because their job looks like "make it green."

M

Maya: The same goes for a skip you mean to remove later. Those skips usually stay, so write the test now.

Summary in three lines

  1. Hook, everyday gate, full gate and required CI checks all run the same scripts.
  2. Coverage floors are per area, set from measurements, and only ever raised.
  3. A red gate is fixed in the code; changing a gate is its own reviewed change, for people and agents.
