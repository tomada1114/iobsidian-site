What do we give up by running the API on Lambda?

After this page you can explain how Lambda runs requests and what a cold start is. You can also say when serverless fits, and when containers or a queue are the better choice.

01How Lambda runs a request

Quickturn uses the default Lambda execution model. An execution environment loads code, initializes the runtime and handles an invocation. Warm environments may be reused, while a new environment incurs initialization latency, called a cold start.

The API initializes configuration and service clients once per environment and can reuse them on warm calls. It does not rely on that reuse for durable state. The learner's drill timer runs on the device, so initialization latency does not consume the timed answer window.

02The front door

API Gateway HTTP APIs provide a comparatively simple HTTP front door. REST APIs add other capabilities such as usage plans and caching. Load balancers and function URLs are additional options with different operation and security models.

Quickturn chooses an HTTP API catch-all route. A CloudFront OAC-protected function URL requires payload hashes for POST and PUT, which would affect clients. A secret-header alternative needs explicit validation and rotation; possession of an obscure URL alone is not access control.

03What serverless gives up

A standard Lambda invocation has a time limit and account-level concurrency constraints. Memory may survive in a warm environment but is never a durable session store. Cost scales with requests and execution duration. These statements concern the default model; Managed Instances and durable workflows have different characteristics.

Quickturn monitors errors and throttles and exercises alarms in development with controlled throttling.

Containers can suit steady load, long-running work or connection patterns that do not fit ordinary request invocations. Their fixed capacity and load balancer costs must be compared with measured Lambda usage. Cold-start assumptions should be tested rather than treated as decisive by themselves.

04Long AI jobs

Long AI work should not be hidden inside an ordinary interactive request. Typed-answer grading goes onto an SQS queue, where a worker performs bounded jobs. Workflow services can coordinate longer sequences and waits.

Quickturn's tutor uses a managed agent runtime for longer sessions. A job or session still needs timeouts, retries, authorization and progress visibility. Choosing a different execution model moves those responsibilities; it does not remove them.

Summary in three lines

  1. Lambda creates environments on demand, so the first request after idle pays a cold start and later ones don't.
  2. Serverless gives up long requests, in-memory state and flat costs, in exchange for no servers and no idle bill.
  3. Pick by the shape of the work: short and spiky suits functions, steady or long suits containers, queues or agent runtimes.
