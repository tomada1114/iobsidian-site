What actually happens when a learner signs in?

A token names a learner, but readable claims alone do not establish identity. The sign-in flow and API verification supply different parts of that trust.

01Who you are, what you may do

Decoding a JWT reveals its claims but does not verify them. Anyone can construct token-shaped text with a desired subject. Authentication establishes the caller; authorization decides which operation and data that caller may access.

OpenID Connect adds identity to OAuth's authorization framework. In Quickturn, the learner is the resource owner and the web backend is the client. Cognito issues tokens, while the API serves protected resources.

02The code flow with PKCE

Quickturn uses authorization code flow with PKCE. The login endpoint creates state and a verifier, then sends the verifier's SHA-256 challenge to Cognito. The callback carries a short-lived code rather than the final tokens.

The backend verifies state and exchanges the code with the verifier and its client credentials. Native clients use the system browser and PKCE without a secret embedded in the app. State, redirect handling and verifier binding have distinct protections and must all be correct.

03Three tokens

The ID token describes authentication to the client, the access token authorizes API use, and the refresh token obtains new access tokens. Quickturn's web session keeps the tokens needed for API access and renewal, not a decoded ID token as authorization evidence.

Verification checks the signature against trusted keys, expiration, issuer, token use and intended client or resource. Cognito access tokens include client_id; an aud claim can also appear when resource binding is requested.

Quickturn uses the same verifier with Cognito keys in production and controlled signing keys in tests. That permits negative tests for incorrect issuer, expiration or client identity without relying on a live sign-in service.

04What a managed service costs

Managed sign-in reduces password and recovery work but adds provider-specific settings, plan choices and migration concerns. Quickturn maps provider subjects to its own learner IDs. Replacing a pool need not rename owned records, although identity mappings still need migration.

Token verification belongs in a path shared by cookie and Bearer authentication. Logs identify which check failed without including the token. A readable token can be a usable credential until its effective expiry or revocation enforcement takes effect.

Summary in three lines

  1. OAuth handles delegated access; OpenID Connect adds a standard sign-in and an ID token.
  2. Quickturn’s web backend exchanges the code using PKCE; native clients instead manage their own protected tokens.
  3. Verify the access token's signature, issuer, token use, client and expiry before trusting its user id.
