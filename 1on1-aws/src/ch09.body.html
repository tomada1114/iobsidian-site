Why write infrastructure as code at all?

A console change makes the API faster, but the next deployment may overwrite it. Reviewed infrastructure code must capture both the setting and its reason.

01Why not the console

A console experiment can reveal that more Lambda memory improves latency. If that change is not reflected in infrastructure code, the next deploy may undo it or leave a drifted setting. Infrastructure as code makes the intended configuration reviewable and reproducible.

Sandbox exploration is useful, but the learned change should be written back into source with its reason. The running account must still be checked against that source.

02How CDK works

CDK runs a program to synthesize CloudFormation templates and deployment assets. CloudFormation calculates and applies a change set. A failed update often rolls back, but rollback can also fail or leave retained resources requiring attention.

Bootstrapping creates deployment resources and roles for an account and Region. Quickturn uses foundation, deployment-access, application and agent stacks, with an explicit deployment order. Development deploys can be automatic while production waits for approval.

03The tools

CloudFormation and SAM define AWS-managed stacks. CDK supplies a programming-language layer that still deploys through CloudFormation. Terraform and similar tools offer broader provider choices with their own state-management model.

Quickturn chooses TypeScript CDK for a shared language and tests across infrastructure involving CloudFront, WAF, Cognito and functions. It does not expect CDK to make CloudFormation deployments instant. A smaller function-focused system could reasonably choose SAM.

04What it costs, and how we test it

Infrastructure abstractions can generate permissions and resources the author did not explicitly write. Test the synthesized result, especially key schemas, retention, billing mode and OIDC trust, rather than rely only on the construct's name.

Focused assertions and resource allowlists make important changes visible. Full-template snapshots can bury them in large diffs. Bundling tests catch deploy-time packaging mistakes; post-deploy reads confirm live settings.

Offline synthesis works when constructs do not require live lookups. Passing synthesis and template tests does not confirm an accepted deployment. The running service’s requested configuration needs a live check.

Summary in three lines

  1. Infrastructure as code defines reviewable intended environments; live checks still detect console drift.
  2. CDK synthesizes CloudFormation templates; CloudFormation applies them as stacks and keeps the state.
  3. Test the synthesized template for what matters, then read the live resource back after a deploy.
