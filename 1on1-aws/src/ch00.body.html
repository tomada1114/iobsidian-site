Engineering Readers: AWS Foundation

A small AWS app still owns access, data and spending decisions. These chapters follow Quickturn from its account boundaries to its monthly bill.

14 pagesAbout 55 minEnglish, B2 · explanatory prose

The example application

Quickturn is a fictional language-learning application. A learner answers a card before a timer ends, then reviews progress and mistakes. Its web, iOS and Android clients share an API.

These chapters use that application to explain concrete engineering choices, their costs and the conditions that would justify a different design. Each chapter stands on its own; no conversation or earlier chapter is needed.

How the pages fit together

The pages

  1. What am I actually responsible for on AWS? — Regions, accounts, and the line between AWS's security and ours.
  2. Why does our deploy have no AWS keys? — Roles hand out short-lived credentials, so there is no long-lived key to leak.
  3. What do we give up by running the API on Lambda? — No servers to run, in exchange for cold starts and limits.
  4. Why doesn't Quickturn have a VPC? — Its present path needs no customer VPC attachment.
  5. How does DynamoDB find my data so fast? — Key ranges avoid reading unrelated learner records.
  6. Why DynamoDB and not PostgreSQL? — A learner boundary built into the keys decided it.
  7. List the questions first, then design the table — Access patterns guide keys, pages and indexes.
  8. What if the app crashes halfway through a write? — One transaction with conditions keeps the log and its summaries in step.
  9. Why write infrastructure as code at all? — Reviewed code describes the intended state; tests and live checks detect drift.
  10. Split what breaks often from what must never be lost — Durable resources have a separate lifecycle and explicit retention policies.
  11. What actually happens when a learner signs in? — A one-time code becomes tokens, and the API verifies before it trusts.
  12. Where should a web app keep its tokens? — HttpOnly cookies keep tokens away from page scripts.
  13. How do we prove one learner can't see another's data? — Stores bound to one learner, with shared isolation tests.
  14. How much will this cost if nobody uses it? — Per-use parts, free tiers and budgets from the first day.

How to read this

Read a chapter in a few minutes, using the diagrams and code examples alongside the explanation. The summaries collect the main decisions; the examples show where those decisions apply.
