One-on-Ones: AWS Foundation

Fourteen short conversations about running a small app on AWS. After them you can explain accounts, access, serverless compute and DynamoDB design. You can also explain infrastructure as code, sign-in, keeping users' data apart, and cost.

14 pagesAbout 2 hoursEnglish, B2 · dialogue

Who's talking

Maya is a staff engineer and the tech lead of Quickturn's platform. Leo was recently promoted to mid-level. He writes TypeScript every day with Claude Code. He wants to explain why the system runs on AWS the way it does. Each page is one of their one-on-ones.

Quickturn is a small company that makes a language-learning app, with a web app and iOS and Android apps on one API. Maya, Leo and Quickturn are fictional.

How the pages fit together

The pages

  1. What am I actually responsible for on AWS? — Regions, accounts, and the line between AWS's security and ours.
  2. Why does our deploy have no AWS keys? — Roles hand out short-lived credentials, so no key can leak.
  3. What do we give up by running the API on Lambda? — No servers to run, in exchange for cold starts and limits.
  4. Why doesn't Quickturn have a VPC? — Nothing private to reach means no network to build and pay for.
  5. How does DynamoDB find my data so fast? — Keys decide where items live, so a Query beats a Scan.
  6. Why DynamoDB and not PostgreSQL? — Known questions and an idle bill near zero decided it.
  7. List the questions first, then design the table — Every access pattern becomes a key before any data exists.
  8. What if the app crashes halfway through a write? — One transaction with conditions keeps the log and its summaries in step.
  9. Why write infrastructure as code at all? — Reviewed code stops drift, and tests check what CDK produces.
  10. Split what breaks often from what must never be lost — Data lives in a retained stack that deploys can't touch.
  11. What actually happens when a learner signs in? — A one-time code becomes tokens, and the API verifies before it trusts.
  12. Where should a web app keep its tokens? — HttpOnly cookies keep tokens away from page scripts.
  13. How do we prove one learner can't see another's data? — Stores bound to one learner, and a test that proves it.
  14. How much will this cost if nobody uses it? — Per-use parts, free tiers and budgets from the first day.

How to read this
