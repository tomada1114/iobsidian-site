誰も使わないとき、いくらかかるか

今日は誰も練習していなくても、保存したデータや時間単位のリソースには費用がかかり続けます。役に立つ費用のモデルには、トラフィックが伸びた場合と、請求が遅れて届くことまで含めます。

01固定費と従量課金

設計を評価するときは、利用者がゼロのときと、トラフィックが今の10倍になったときに、それぞれいくらかかるかを問います。時間単位のインフラ、保存しておくストレージ、月額のプランは、呼び出し回数、リクエスト数、ログの量とは違う動き方をします。使われていないときの費用が低いというだけでは、成長したときの請求は予測できません。

Quickturn は、現在のワークロードに不要な NAT、ロードバランサー、インターフェースエンドポイントの費用を避けています。料金の例はリージョン、プラン、時期によって変わるので、恒久的な料金として扱わないでください。

02避けているもの、無料のもの

監視とデータの保持も、費用のモデルの一部です。リクエストごとに構造化したログを1行出し、ログの保持期間を区切り、アラームの組み合わせを明示しておけば、デバッグ用の出力が際限なく増えることを避けられます。無料枠や CDN のプランについては、「無料」がすべての部品を賄うと思い込まず、その時点の適用条件を確かめる必要があります。

API Gateway には利用料金がかかりますが、チームは入口としての働きと引き換えにそれを受け入れています。予測額のアラートが届いたら、サービスとアカウントごとに原因を調べ、実験のあとに動かしたままのリソースがないかも確かめます。安いインフラでも、支出の歯止めは必要です。

03初日から置く歯止め

Quickturn は、月ごとの実績額と予測額のアラートを設定し、強い措置の前に、低めのしきい値で警告を出します。機能ごとのタグや推論プロファイルを使うと、モデルの利用料を機能ごとに振り分けやすくなります。こうした制御は、まとまった額の有料の実験を始める前に設定しておくべきです。

請求データは遅れて届きます。予算アクションはそれ以降のモデルの呼び出しを拒否できますが、支出がちょうど予算で止まることまでは保証できません。学習者ごとの予約は、新しい呼び出しが始められる範囲を制限します。呼び出しごとの利用状況のテレメトリーを見れば、どの機能でお金がかかったかがわかります。

04節約が高くつくとき

負荷が継続的に高くなると、リクエスト単位の実行より、常時稼働の容量のほうが安くなることがあります。エンジニアの時間も費用のうちです。ほかに利点がないのに、数ドルを節約するために複雑な移行をするのは割に合いません。

アカウント全体でモデルを止めるキルスイッチは、機能が使えなくなることと引き換えに費用を抑えます。正当な利用でも作動することがあるので、アラート、復旧の手順、はっきりした担当者が欠かせません。どちらか一方で費用の問題がすべて解決すると考えず、アカウント単位の制御とリクエスト単位の上限を組み合わせてください。

3行まとめ

  1. 時間単位の部品と使った分だけの部品を分け、それぞれトラフィックがゼロのときと10倍のときにいくらかかるかを問います。
  2. 使われていないときの費用をゼロに近づけ、無料枠が何を賄うのかを把握しておきます。
  3. 初日から予算を設定し、利用が暴走しうるところには予算アクションとユーザーごとの上限を置きます。
