How does DynamoDB find my data so fast?

The API needs one learner’s rounds, not every learner’s records. A partition key and sort-key range let DynamoDB target that question.

01Items, keys and partitions

DynamoDB stores items with attributes and a primary key. Quickturn uses a partition key and sort key. The partition key selects a logical collection, while DynamoDB distributes storage internally. The sort key orders items for range access within that key.

A full key allows GetItem to retrieve one item directly. Quickturn's partition key identifies the learner, while the sort key identifies settings, rounds, answers or other owned records. Logical learner partitions should not be confused with a permanent one-to-one mapping to physical storage partitions.

02Query versus Scan

A Scan reads table items before applying a filter. Filtering for one learner therefore does not save the cost of reading other learners. Query instead selects a partition key and can restrict the sort-key range or prefix.

Quickturn maps request-path reads to those keys and follows pagination, whose response pages are bounded by size. It checks item kinds when a prefix returns both rounds and answers. A secondary index can support another key pattern, but it creates additional write, storage and consistency considerations.

03Capacity, consistency and size

On-demand capacity suits irregular traffic; provisioned capacity can suit predictable load. Either can encounter throttling, including concentrated traffic on a hot key. Capacity choice does not remove the need for alarms.

DynamoDB reads are eventually consistent by default. Quickturn requests strong consistency where immediately reflecting an accepted answer matters. Strong reads consume more capacity and are not available on global secondary indexes.

An item is limited to 400 KB. Store an unbounded answer history as separate items rather than continually extending one record. Multi-item transactions can provide atomic changes within their limits.

04What you give up

DynamoDB offers managed key-based access but gives up ordinary relational joins and flexible exploration. Access patterns need planning. Quickturn uses exports for broader reporting instead of scanning live learner request paths.

If the required questions are still unknown or relationships and reporting dominate, a relational database may be easier to evolve. Point-in-time recovery restores another table. A tested recovery procedure must then put that restored data back into service.

Summary in three lines

  1. The partition key picks where an item lives; the sort key orders items inside that partition.
  2. Get by full key or Query one partition; a Scan reads everything, and a filter only trims the result.
  3. Choose capacity mode and consistency on purpose, and list your questions before you design the table.
