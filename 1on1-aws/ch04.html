Why doesn't Quickturn have a VPC?

After this page you can explain how a CDN serves an app and its API from one origin. You can also say what a VPC is for, what it costs, and when you really need one.

About 8 min readWhiteboard room

In this page

  • What sits between the browser and our code?
  • Why does one origin matter?
  • What is a VPC, and why don't we have one?
  • When would we need a VPC?

The whiteboard room. Leo has a tutorial open on his laptop.

01The edge

L

Leo: I followed an AWS tutorial last night. Step one was "create a VPC with public and private subnets". We don't have a VPC at all. Are we insecure?

M

Maya: Let's check. Before we get to VPCs, what do you think sits between a learner's browser and our code?

L

Leo: CloudFront, I think. Then the API.

M

Maya: Right. CloudFront is a CDN, a content delivery network. It serves content from locations close to the user, and it caches what it can.

L

Leo: And the web app's files come from S3?

M

Maya: From an S3 bucket that blocks all public access. Nobody can read it directly, not even with the exact URL.

L

Leo: Then how does CloudFront read it?

M

Maya: Through origin access control. The bucket's policy lets only this one CloudFront distribution read it. Everyone else gets "access denied".

L

Leo: And traffic between CloudFront and the API?

M

Maya: HTTPS only, on both paths. The bucket also refuses any request that isn't encrypted, so even a mistake in our settings can't send files in plain text.

L

Leo: What about links inside the app, like /records? There's no file with that name.

M

Maya: A tiny CloudFront Function runs at the edge. It sends client routes like that to index.html, and the app's router takes over in the browser.

L

Leo: So CloudFront serves the app. And the API?

M

Maya: That's the interesting part. Let me draw the whole front door.

02One origin for two backends

L

Leo: So /* goes to the bucket, and /api/* goes to the API.

M

Maya: Right. The bucket path is cached. The API path is never cached, and CloudFront forwards all the browser's headers except Host.

L

Leo: Why not cache the API too? Some reads don't change often.

M

Maya: Every API response belongs to one signed-in learner. A cache that mixes them up would show one learner another's data. Not caching at all is the safe default.

L

Leo: Okay. Why put both behind one address, though? The API could have its own hostname.

M

Maya: What does the browser see when both are on one domain?

L

Leo: One origin. The same scheme, host and port for everything.

M

Maya: So what happens to the sign-in cookie?

L

Leo: It goes with every API call, because it's the same origin. No cross-site cookie rules.

M

Maya: And no CORS to set up. CORS is the browser's rule for calls between different origins. Every rule you don't configure is one you can't get wrong.

L

Leo: What would a separate API hostname give us, then?

M

Maya: It would separate the API from the web app's releases, which suits the native apps. But CORS comes back, and the cookie setup gets harder.

L

Leo: So it's a real trade-off, not a mistake either way.

M

Maya: Yes. We chose one origin, and we look at it again as the native apps grow.

03What a VPC is for

L

Leo: Now the VPC. What is it, really?

M

Maya: A VPC is a private network you define inside AWS. You split it into subnets, set route tables that say where traffic may go, and put security groups on resources, like firewalls.

L

Leo: And "public and private subnets"?

M

Maya: A public subnet has a route to the internet. A private subnet doesn't. You put a database in the private one, so nothing outside can reach it.

L

Leo: That sounds safer. Why don't we do that?

M

Maya: Here's the catch. Code in a private subnet can't reach the internet, or even AWS's public service endpoints, without help.

L

Leo: What kind of help?

M

Maya: A NAT gateway, which lets private resources call out. Or VPC endpoints, private doors to specific AWS services. Let me draw a typical setup next to ours.

L

Leo: The NAT gateway costs money even when nobody uses it?

M

Maya: It bills every hour, plus a charge per gigabyte. Interface endpoints bill per hour too. Only the gateway endpoints for S3 and DynamoDB are free.

L

Leo: So our Lambda just calls DynamoDB over the public endpoint?

M

Maya: Yes, and Cognito too. That sounds scary until you ask: what stops a stranger from calling DynamoDB on our table?

L

Leo: IAM. They'd need credentials with permission on our table.

M

Maya: Right. Every call is signed and checked by IAM. Our protection comes from IAM and authentication, not from where the code sits on a network.

L

Leo: So the tutorial's VPC wasn't wrong. It was solving a problem we don't have.

M

Maya: That's exactly the point.

04When you do need a VPC

L

Leo: When would we need one, then?

M

Maya: When there's something private to reach. A relational database like RDS or Aurora usually lives in private subnets.

L

Leo: So if we ever moved to PostgreSQL, the VPC comes with it.

M

Maya: Most likely, and the NAT or endpoint costs come with it too.

L

Leo: What other cases?

M

Maya: A company's private data reached over a VPN or Direct Connect. Services meant to be internal only. And compliance rules that require private network paths.

L

Leo: The enterprise AI agents you built before, did they need one?

M

Maya: Often, yes. The agent had to read internal systems that only existed on a private network. There the VPC wasn't a choice.

L

Leo: And for us, adding a NAT gateway is a big decision?

M

Maya: It needs the owner's OK first. It adds a fixed monthly cost to an app that otherwise costs almost nothing when idle.

L

Leo: What protects the edge, then, if not a network?

M

Maya: The CloudFront distribution has WAF rate-based rules, which slow down anyone sending too many requests. It runs on a CloudFront flat-rate plan: the Free plan, then Pro as traffic grows.

L

Leo: So security lives in layers: WAF at the edge, IAM on every call, and sign-in in the app.

M

Maya: Yes. A VPC is one more layer when you have private things to hide. We don't, so it would be cost without benefit.

05Leo explains it back

M

Maya: Say a new teammate sees our setup and asks where the VPC is. What do you tell them?

L

Leo: CloudFront is our single front door. Static files come from a private bucket that only CloudFront can read.

L

Leo: And /api goes to the API, so the browser sees one origin. Cookies just work, with no CORS.

L

Leo: We don't need a VPC. Every AWS service we call has a public endpoint, and IAM checks each call.

M

Maya: And when would that change?

L

Leo: When we have something private to reach, like a relational database or a system on a private network.

M

Maya: Name the price, too: then NAT gateways and endpoints add cost every hour, used or not. That's why adding one needs a real reason, not a tutorial's first step.

Summary in three lines

  1. A CDN can serve a private bucket and route /api/* to the API, so the browser sees one origin.
  2. Without private resources, IAM on every call protects the app; a VPC adds nothing but cost.
  3. Add a VPC when you must reach something private, and budget for NAT gateways and endpoints billed by the hour.
